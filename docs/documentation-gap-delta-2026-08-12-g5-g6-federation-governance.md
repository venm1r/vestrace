## G5 scope implemented

1. Added typed `FederationRelationshipId` and `FederationTrustDecisionId` identifiers generated by the domain.
2. Added exact `RemoteIdentity` binding to remote workspace, remote principal, issuer and subject.
3. Added local `FederationTrustPolicy` with trusted issuer, accepted remote profiles, operation set and exact policy version.
4. Added `RemoteQualificationEvidence` as bounded metadata and validated it against local issuer/profile policy before relationship establishment.
5. Added explicit relationship lifecycle (`Active`, `Suspended`, `Revoked`, `Expired`, `Deleted`) with fail-closed trust evaluation for identity, workspace, operation, policy version and validity mismatches.
6. Added `evaluate_federated_memory_access`: a passing federation trust decision is insufficient; G4 source grant, target mount and target policy must also allow the operation and must bind to the exact remote/source and local/target workspaces.
7. Kept trust decisions separate from `SharedMemoryRef`; no trust-only conversion, local derivation or transitive authority path was added.

## G6 scope implemented

1. Added `GateEvidenceStatus` (`Pass`, `Fail`, `NotApplicable`, `Skipped`, `Inconclusive`) and explicit evidence origin including `RemoteSelfAsserted`.
2. Added `GovernanceFederationGate` for `FEDERATION` and `TRUSTED` targets. It derives the existing profile closure, filters the registry to required MUST requirements, and adds the documented federation/governance hard-gate IDs.
3. The gate rejects unsupported profile claims, missing or duplicate evidence, failed/not-applicable/skipped/inconclusive results, missing evidence references, missing exact policy versions for GOV-024/GOV-025, and remote self-asserted evidence.
4. A `FEDERATION` evidence set cannot pass a `TRUSTED` evaluation because the additional recovery/governance/qualification closure remains required.

## Explicit non-claims

This is an additive in-memory domain and evidence-gate slice. It does not claim:

- durable federation relationship, trust-decision, evidence, audit or QualificationBundle persistence;
- cryptographic signature/attestation verification, remote transport, federation protocol or adapter wiring;
- HTTP, MCP, CLI, worker, retrieval, cache, index, model/provider, export or local-derivation enforcement;
- complete DataPolicy/classification/destination implementation or PostgreSQL runtime/RLS federation evidence;
- a qualified GOVERNANCE, FEDERATION, TRUSTED or v0.4 release profile.

The next gate is H1: invariant registry and health-finding evidence. The G5/G6 federation and hard-gate domain boundaries remain available for later runtime/qualification wiring.
