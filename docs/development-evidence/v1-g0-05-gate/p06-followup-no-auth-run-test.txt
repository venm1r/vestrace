--- 3.2 Root cause: a THIRD gap of the same shape, one layer deeper ---

  migrations/0178_model_revisions_and_binding_snapshots.sql:150-163 requires the
  model revision's `execution_guard_id` to be EXACTLY the connection revision's
  own guard:

      IF NOT EXISTS (
          SELECT 1
            FROM connection_revisions AS revision
            JOIN connection_execution_guards AS guard
              ON guard.id = revision.execution_guard_id
             AND guard.workspace_id = revision.workspace_id
             AND guard.connection_id = revision.connection_id
           WHERE revision.workspace_id = target_workspace_id
             AND revision.connection_id = target_connection_id
             AND revision.id = target_connection_revision_id
             AND revision.execution_guard_id = target_execution_guard_id
      ) THEN
          RAISE EXCEPTION 'model revision requires its exact referenced connection guard'
              USING ERRCODE = '23514';
      END IF;

  The required value, read directly from the database:

  $ docker exec vestrace-postgres-1 psql -U vestrace_bootstrap -d vestrace \

  The console sent `d96e733d-89a6-45a0-8197-18bbd7b5c905`, a fresh
  `crypto.randomUUID()` (apps/console/src/routes/ModelsPage.tsx:79). It can

    * the connection's guard id was itself minted client-side at Connection

--- 5.5 Operational concern: the retry is a hot loop, not a backoff ---

  `poll_qualification_work` releases a failed probe as
  `QualificationWorkOutcome::RetryableFailure` (worker.rs:610-613), which makes
  the job immediately reclaimable. With a deterministic failure, the worker
  reclaims and refails about twenty times per second, forever, writing a durable
  `external_effect_authorizations` row each time:

  $ ... -c "select count(*) from external_effect_authorizations;"
   total_denies

           8731

  8731 denial rows from one stuck job in roughly eight minutes. The loop also
  survived the restart in section 7 and resumed at the same rate. A deployment
  that hits this would accumulate rows at ~1.5M/day from a single stuck job.
