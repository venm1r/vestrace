# G4 Cross-Workspace Sharing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the documented G4 grant-plus-mount domain boundary so cross-workspace memory access requires an exact source grant revision and explicit target acceptance, while revoke/expiry/staleness deny future disclosure without erasing historical disclosure evidence.

**Architecture:** Add an in-memory enterprise sharing kernel beside the existing legacy `CrossWorkspaceMemoryGrant`. `MemoryShareGrant` owns an immutable `MemoryShareGrantRevision`; `MemoryMount` is target-owned and accepts one exact revision under an independent `TargetSharePolicy`. Access evaluation intersects source operations, mount operations, and target policy. `SharedMemoryRef` is a namespaced value object and is never converted to local `MemoryId`; durable persistence, API wiring, and SQL/RLS migrations remain outside this additive G4 slice.

**Tech Stack:** Rust workspace, `vestrace-domain`, `chrono::DateTime<Utc>`, typed UUID IDs, `serde`, `schemars`, cargo test, JSON qualification fixtures, Markdown implementation ledgers.

## Global Constraints

- IDW-004: Cross-workspace Memory access requires explicit source grant and target acceptance.
- IDW-005: Wildcard target grants are prohibited.
- IDW-006: Mounted memory cannot be automatically re-shared to a third workspace.
- IDW-007: Source and target policy must be checked independently.
- IDW-008: Revoked, expired, or stale mounts must not return content/reference access.
- IDW-009: `SharedMemoryRef` preserves source workspace plus exact memory/revision/grant context.
- IDW-010: `SharedMemoryRef` must not substitute for a local `MemoryId`.
- IDW-013: Revocation must not rewrite historical disclosure evidence.
- IDW-014: Cross-workspace access must not require removing normal workspace isolation/RLS.
- The existing `CrossWorkspaceMemoryGrant` and migration `0087` are preserved as legacy seeds; they never auto-upgrade into an accepted mount.
- This slice is additive and in-memory. It must not claim durable grant revisions, mount persistence, cache/index invalidation, HTTP/MCP wiring, or PostgreSQL runtime evidence.
- Preserve all unrelated dirty work and do not commit, reset, rebase, or broad-format the worktree.

### Task 2: Implement immutable source grant revisions and target acceptance

**Files:**
- Modify: `crates/vestrace-domain/src/enterprise/sharing.rs`
- Modify: `crates/vestrace-domain/src/enterprise/mod.rs`
- Modify: `crates/vestrace-domain/src/id.rs`
- Modify: `crates/vestrace-domain/src/lib.rs`

**Interfaces:**
- Consumes: the RED tests from Task 1 and the existing enterprise legacy bridge.
- Produces: validated constructors and lifecycle methods with these stable shapes:
  - `MemoryShareGrantRevision::issue(spec: MemoryShareGrantRevisionSpec, created_at: Timestamp) -> Result<Self, DomainError>`; the authoritative revision ID is generated inside the constructor.
  - `MemoryShareGrant::issue(revision: MemoryShareGrantRevision, created_at: Timestamp) -> Result<Self, DomainError>`; the authoritative grant ID is generated inside the constructor.
  - `MemoryShareGrant::revoke(&mut self, at: Timestamp) -> Result<(), DomainError>`.
  - `TargetSharePolicy::new(workspace_id: WorkspaceId, principal_id: PrincipalId, operations: BTreeSet<ShareOperation>, valid_until: Option<Timestamp>) -> Result<Self, DomainError>`.
  - `MemoryMount::accept(acceptance: MemoryMountAcceptance, grant: &MemoryShareGrant, target_policy: &TargetSharePolicy, accepted_at: Timestamp) -> Result<Self, DomainError>`; the authoritative mount ID is generated inside the constructor.

- [x] **Step 1: Add typed IDs and export the module**

Add `MemoryShareGrantRevisionId` and `MemoryMountId` through the existing `domain_id!` macro. Add `mod sharing; pub use sharing::*;` to `enterprise/mod.rs`, and re-export the G4 types from the root domain module if the existing public API convention requires it.

- [x] **Step 2: Implement exact-target and immutable-revision validation**

Use `ShareTarget::ExactWorkspace(WorkspaceId)` and `ShareTarget::AnyWorkspace`. `MemoryShareGrantRevision::issue` must reject `AnyWorkspace`, identical source/target workspaces, empty operation sets, `ShareOperation::ReShare`, blank source generation, and `valid_until <= valid_from`. Store the resolved exact target workspace in the immutable revision. The revision must contain exact `MemoryId`, `MemoryRevisionId`, and source generation.

- [x] **Step 3: Implement target-owned acceptance validation**

`MemoryMount::accept` must require an active source grant at `accepted_at`, the exact grant ID and revision ID, exact target workspace, target policy principal/workspace match, non-empty accepted operations, accepted operations as a subset of the source revision operations and target policy operations, and a mount expiry no later than the grant/policy expiry. The mount stores only the exact source reference context and target-owned state; it does not copy source content.

- [x] **Step 1: Add RED tests for the remaining behavior**

Ensure the tests assert that source revocation, source expiry, mount stale state, mismatched grant revision, target-policy denial, and `ReShare` all deny reference access. Record a disclosure before revocation and assert the same immutable `SharedMemoryRef` remains in `disclosures()` after `sync_with_source` marks the mount stale.

- [x] **Step 2: Implement fail-closed lifecycle synchronization**

`sync_with_source` must mark a mount `Revoked`, `Expired`, or `Stale` when the source relationship is no longer active or its exact grant/revision identity no longer matches. It must never delete or rewrite disclosure records. `shared_ref` must verify exact identity and active state before returning a namespaced reference.

- [x] **Step 3: Implement the policy intersection evaluator**

Check source grant activity and operation first, then exact mount identity/state/operation, then target workspace/principal/operation/validity. Return an auditable `ShareAccessDecision` with `allowed`, `reason`, grant ID, revision ID, mount ID, and timestamp. `ReShare` must always return `TransitiveSharingProhibited` in this G4 boundary.
