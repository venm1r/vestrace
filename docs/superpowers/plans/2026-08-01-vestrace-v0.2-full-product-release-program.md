# Vestrace v0.2 Full Product Release Program

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this program one review-gated slice at a time. Execute the linked detailed implementation plan for each slice; do not reconstruct it from this summary.

**Documentation status:** Planning artifact only. Do not create implementation branches, install dependencies, generate code, modify schemas, update CI or implement production behavior until the user explicitly ends the documentation-only phase.

**Goal:** Deliver the approved v0.2 full product as a Windows-first, Docker Compose product with the complete H1-H11/H9A platform, AG-UI, A2A, SDKs, administration, all six State Engine follow-up extensions, Task Workbench and Memory Console.

**Architecture:** This document is the program-level dependency and evidence plan. Each subsystem remains owned by its existing detailed implementation plan and lands through a bounded branch, tests, review and merge gate. A single progress ledger records immutable merge SHAs, migrations, evidence and blockers. Migration-owning slices are serialized. Final qualification composes public contracts only and does not create a second runtime or bypass domain authority.

**Tech Stack:** Rust Edition 2024 workspace; PostgreSQL with forced RLS; Docker Compose; H11 HTTP/CLI/MCP and generated Rust/TypeScript/Python SDKs; H11A AG-UI; H9A A2A; React/Vite TypeScript console; Vitest, Playwright and axe-core; Windows 11 with Docker Desktop/WSL2 as the primary release environment and Linux as reference CI.

## Global Constraints

- The approved scope is the full v0.2 product, not a reduced MVP: H1-H11, H9A, Personal/Team/Embedded deployment modes, A2A, SDKs, backup/restore/upgrade administration, Web UI and all six follow-up extensions are mandatory.
- The default product profile is local single-user through Docker Compose and localhost Web UI, with no registration flow.
- The primary supported host is Windows 11 with Docker Desktop/WSL2. Linux CI is mandatory but does not replace Windows qualification.
- OpenAI-compatible provider configuration is available through the Web UI; secret values are stored only through H8 and are never readable back in plaintext.
- Local workspace file tools require exact approval before every write. The baseline execution profile is one sequential agent with checkpoints.
- Memory candidates require explicit edit/approve/reject review before commitment.
- Product UI remains a projection-and-command client. Run, Memory, policy, approval, budget, credential, Artifact and sharing authority stay server-side.
- Existing plans are authoritative for subsystem internals. This program may order or gate them but must not silently change their contracts.
- Every slice uses TDD, focused verification, independent review, an atomic commit series and a clean merge into current `main` before a dependent slice starts.
- Existing unrelated work is preserved. No reset, broad reformat, opportunistic refactor or dependency upgrade is allowed.
- A passing component suite proves only its slice. Completion requires the final cross-surface, restart, fault, backup/restore, security, accessibility and Windows evidence gates.
- No migration-owning branches execute concurrently from a stale base. Rebase-free merge sequencing and current-main migration verification are required before each migration slice starts.
- Forward-only migrations are immutable after merge; follow-up corrections receive a new number.
- External data, mounted Memory, model output, webhooks, A2A payloads and generated UI definitions are untrusted unless an explicit policy says otherwise.
- `OutcomeUnknown` is never rendered or handled as failure, success or permission to retry blindly.
