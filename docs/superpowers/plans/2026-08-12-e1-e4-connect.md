**Goal:** implement the v0.6 Connect contract for explicit external-effect intents, adapter-declared delivery semantics, receipt/UNKNOWN handling, reconciliation, compensation, deterministic fault cases, and the Connect evidence gate without claiming durable provider qualification.

**Architecture:** Add a domain-owned `external_effects` contract that is immutable from prepare through authorization, and a narrow synchronous adapter trait that can only return typed dispatch observations. Keep canonical intent/receipt/reconciliation facts separate from logs and existing tool projections. Add a deterministic fault evaluator and milestone gate as evidence-only boundaries; do not create a second execution runtime or retrofit the legacy tool status model.

**Tech Stack:** Rust 2024, `vestrace-domain`, `vestrace-application` adapter boundary, serde/schemars, chrono timestamps, workspace integration tests and JSON qualification fixtures.

## Global Constraints

- `ExternalEffectIntent` is immutable after authorization and must exist before dispatch.
- Adapter delivery, idempotency, reconciliation, reversibility and dry-run semantics are declared, never inferred from agent behavior.
- `UNKNOWN` is first-class; it is not `FAILED` and cannot auto-retry without adapter-proven retry-safe semantics.
- Reconciliation uses the strongest available evidence and preserves evidence references.
- Compensation is a new external effect with a new intent/authorization/receipt relation; it is not rollback or history deletion.
- Receipts are evidence of dispatch/acknowledgement, not automatic proof of the desired business outcome.
- This slice is additive and in-memory/contract-first. No migrations, durable provider adapter, secret storage, or release qualification is added.
- Existing dirty work and generated artifacts must remain untouched; no reset, cleanup, rebase or commit.
