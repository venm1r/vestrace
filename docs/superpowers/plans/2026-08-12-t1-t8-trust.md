# T1–T8 Trust Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** implement the additive v1.0 Trust contract for incidents, containment, recovery/revalidation, secret and key references, data governance, retention/deletion verification, governed export/audit integrity, qualification bundles/baselines, and the TRUSTED evidence gate.

**Architecture:** Keep canonical Trust semantics in a domain-owned contract module. Reuse the existing health, authorization, security classification, conformance requirement registry, and execution/effect concepts without introducing a second runtime. Store only opaque secret/key references and audit digests in durable-shaped models. Keep provider/KMS, durable repositories, and deployment qualification outside this slice.

**Tech Stack:** Rust 2024, `vestrace-domain`, serde/schemars, chrono timestamps, SHA-256 audit/target digests, workspace integration tests and JSON qualification fixtures.

## Global constraints

- Incident, containment, recovery, revalidation, governance, deletion, export, and qualification states remain explicit and distinct.
- Restart/recovery never directly restores `TRUSTED`; only successful evidence-backed revalidation plus the qualification gate can do so.
- Secret material and key bytes never enter durable-shaped models, receipts, audit entries, or qualification evidence.
- Data classification propagates conservatively; declassification is a separate governed decision with exact policy provenance.
- Retention expiry is not deletion; holds block automated disposal; deletion verification records remaining copies and semantics.
- Export is a governed external effect with exact scope, recipient, purpose, classification, provenance, and integrity metadata.
- TRUSTED qualification is target-identity-bound and rejects missing, skipped, inconclusive, failed, stale, or self-asserted evidence.
- This slice is additive and contract-first/in-memory. No migrations, provider/KMS wiring, durable repositories, or v1.0 qualification claim.
- Preserve all unrelated dirty work and generated artifacts; do not reset, clean, rebase, stage, or commit.
