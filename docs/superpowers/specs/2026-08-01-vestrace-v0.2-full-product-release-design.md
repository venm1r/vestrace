# Vestrace v0.2 Full Product Release Design

**Статус:** утверждённый design scope; документационный артефакт.
**Основной профиль:** self-hosted, Windows 11 + Docker Desktop/WSL2.
**Reference runtime:** Linux CI.
**Product surface:** полный Web UI, HTTP/SSE, AG-UI, CLI, MCP, Rust/TypeScript SDK и A2A.

## 1. Назначение

Этот документ определяет границу первого полного продуктового релиза Vestrace v0.2. Он не заменяет существующие архитектурные спецификации и implementation plans. Он связывает их в один release contract и добавляет утверждённые продуктовые решения:

- первый релиз является полным self-hosted v0.2, а не уменьшенным техническим MVP;
- H1–H11, H9A, H11A и H11B входят в release scope;
- все шесть утверждённых State Engine follow-up concerns входят в release scope;
- Web UI обязателен и включает полноценные Task Workspace и Memory Console;
- основной first-run профиль остаётся локальным single-user без регистрации;
- Team и Embedded profiles также входят в release qualification;
- Windows 11 с Docker Desktop/WSL2 является основной поддерживаемой платформой;
- Linux является reference runtime для CI и compatibility gates.

Создание или слияние этого документа не разрешает implementation branch, Rust/TypeScript changes, migrations, dependency installation, Docker startup, provider calls или runtime mutations. Implementation начинается только после отдельного утверждённого implementation plan и явного завершения documentation-only phase.

## 3. Release scope

### 3.1 Обязательные подсистемы

Первый релиз включает:

1. Vestrace v0.1 Memory Plane, retrieval, Context Pack и cognitive assets.
2. H1 durable Run journal, checkpoints, leases, restart и replay boundaries.
3. H2 policies, approvals, budgets и exact authorization tickets.
4. H3 native OpenAI-compatible provider path и выбранный model-loop binding.
5. H4 tool runtime, protected preparation/commit и sandbox boundaries.
6. H5 planning, delegation и bounded SubRuns.
7. H6 Context, Artifacts, evidence, safe previews и exports.
8. H7 conversations, channels, triggers и durable interaction facts.
9. H8 connections, credential broker и cryptographic operations.
10. H9 Agent Packages и extension registry.
11. H9A A2A interoperability gateway.
12. H10 observability, evaluation, correction и unbypassable completion gate.
13. H11 product APIs, SDKs, deployment profiles, backup, restore и upgrade.
14. H11A AG-UI interaction gateway.
15. H11B first-party Web UI и design system.
16. State capture profiles.
17. Durable event schema compatibility.
18. Signed portable Run export.
19. Verified inbound и signed outbound webhooks.
20. Workspace envelope encryption.
21. Cross-workspace memory sharing.

### 3.2 Default Personal experience

Полный product scope не означает default autonomy. Personal first-run experience использует:

- одного локального principal без signup;
- один Personal workspace;
- один последовательно исполняемый reference agent;
- OpenAI-compatible provider, настроенный через Web UI;
- H8-backed сохранение API key;
- выбранную пользователем локальную рабочую папку;
- bounded file read/create/update tools внутри этой папки;
- отдельное Human Request перед каждой записью файла;
- checkpoints и безопасное resume;
- memory candidates, которые пользователь редактирует, подтверждает или отклоняет.

SubRuns, дополнительные tools, triggers, remote agents, packages, extensions и cross-workspace sharing поддерживаются релизом, но не включаются неявно и не расширяют authority reference agent.

### 3.3 Не входит

Сохраняются утверждённые exclusions H11/H11B:

- managed public SaaS;
- public signup, billing и OIDC/browser SSO;
- обязательные Kubernetes, Kafka или NATS;
- публичный marketplace;
- mobile native application;
- unrestricted browser automation;
- direct agent SQL;
- hidden chain-of-thought storage;
- automatic activation пакетов, extensions, triggers, connections или shared mounts;
- effectful replay или blind retry операций с неоднозначным исходом;
- database down-migrations;
- cross-deployment cloning через restore;
- автоматическая authority elevation из model, tool, webhook, mounted memory или remote agent content.

## 4. Архитектурные слои

```text
Product surfaces
  Web UI | HTTP/SSE | AG-UI | CLI/MCP | Rust/TS SDK | A2A
                         ↓
Shared application commands, queries, DTOs and policy gates
                         ↓
Harness application plane
  H1 Runs | H2 Policy | H3 Models | H4 Tools | H5 Planning
  H6 Context/Artifacts | H7 Channels | H8 Secrets
  H9 Packages | H9A A2A | H10 Evaluation
                         ↓
Authoritative v0.1 foundation
  Memory Core | Retrieval | Cognitive Assets | PostgreSQL forced RLS
  Artifact/backup byte stores
```

Все product surfaces используют одни application services. Transport adapters не создают отдельные idempotency, lifecycle, approval, cursor или retry semantics.

Web UI является клиентом публичных H11/H11A contracts. UI state хранит presentation preferences, route state и optimistic drafts, но не становится источником истины для Run, approval, Artifact, Memory, policy, credential, webhook, export, backup или sharing lifecycle.

## 5. Deployment profile

### 5.1 Primary platform

Официальный primary profile первого релиза:

```text
Windows 11
└── Docker Desktop + WSL2
    └── Docker Compose
        ├── Vestrace Web UI
        ├── Vestrace server
        ├── Vestrace worker
        ├── PostgreSQL 17 + pgvector
        ├── rootless-compatible sandbox runtime
        ├── configured Artifact store
        └── independent encrypted Backup store
```

Linux выполняет reference CI, integration, sandbox, Compose, backup/restore и release compatibility gates. macOS не является first-release release-blocking platform.

### 5.2 Bootstrap

Первый запуск выполняется через Web UI:

```text
Compose health
→ Personal bootstrap
→ OpenAI-compatible endpoint
→ model selection
→ H8 API-key enrollment
→ bounded workspace folder
→ diagnostics
→ Ready
```

Onboarding не отображает сохранённый API key после submit, не помещает его в browser persistence и не разрешает provider test обходить H8, redaction или egress policy.

## 6. Information architecture

Desktop Web UI использует единый Workbench:

```text
App shell
├── persistent left navigation
├── primary workspace
└── contextual Inspector
```

Top-level navigation:

```text
Home
Tasks
Memory
Artifacts
Automation
System
```

- `Home` показывает health, recent Runs, unresolved Human Requests, memory candidates и operational warnings.
- `Tasks` содержит Runs discovery и Task Workspace.
- `Memory` содержит полноценную Memory Console.
- `Artifacts` предоставляет safe preview, lineage, versions и governed export.
- `Automation` содержит schedules, triggers, inbound/outbound webhooks и delivery state.
- `System` содержит providers, Connections, policies, packages, extensions, remote agents, evaluations, audit, schemas, backup, restore и upgrade.

Inspector является secondary route state. Его закрытие восстанавливает тот же primary route, selection, scroll, plan state и conversation position.

## 7. Task Workspace

Task Workspace использует вертикальный гибрид Plan + Chat.

Основная область содержит:

1. Goal and status header.
2. Adaptive Plan.
3. Conversation.
4. Final Result/Result Report после завершения.

Plan расположен над Chat и может быть свёрнут. Свёрнутая строка обязана показывать:

- progress `completed/total`;
- текущий шаг;
- число blocked steps;
- unresolved Human Request count;
- checkpoint/stale indicator, если применимо.

Сворачивание Plan не скрывает Human Requests, waiting-approval state или Run failure. Inspector содержит exact approval, proposed patch, evidence, Artifacts, memory candidates и Run history.

Chat является полноценным управлением Run, но сообщение не заменяет typed command. Redirect, pause, resume, approve, reject, revise-plan и cancel проходят через отдельные application commands.

### 7.1 File operation flow

```text
bounded read
→ exact source revision/hash
→ proposed patch
→ policy evaluation
→ Human Request with exact patch hash
→ approval
→ pre-commit revalidation
→ write
→ deterministic verification
→ evidence
```

Изменение файла между proposal и commit делает approval stale. UI требует новое предложение и не предлагает применить устаревший patch.

## 8. Memory Console

`Memory` является отдельным top-level product domain. Основной desktop layout:

```text
global navigation
→ search/result library
→ selected Memory detail
→ contextual Inspector
```

### 8.1 Library

Library предоставляет:

- text, structured, temporal и origin filters;
- type, status, sensitivity, workspace, agent, source и conflict filters;
- explicit degraded-search warnings;
- origin и trust labels;
- active/candidate/conflict/deleted state;
- pagination/cursors без unbounded result materialization.

### 8.2 Detail

Detail показывает текущую revision, safe content view, structured payload, status, sensitivity, confidence/importance, effective policy и доступные governed actions.

### 8.3 Inspector

Inspector показывает:

- provenance;
- immutable revision history;
- derivations;
- relations;
- conflicts;
- retrieval/use explanations;
- audit facts;
- shared origin/grant/mount state, когда применимо.

### 8.4 Governed lifecycle

Memory Console поддерживает:

- review/edit/approve/reject Candidate;
- correction как новую revision;
- supersede с сохранением истории;
- conflict proposal и explicit resolution;
- soft delete;
- protected hard purge с exact target, policy, approval и cleanup evidence;
- controlled sharing grant/mount review;
- local import proposal с полным provenance.

UI никогда не изменяет historical revision, не трактует source confidence как local trust, не превращает mounted content в local Memory и не объявляет purge/erasure завершённым при unknown downstream state.

## 9. Основные пользовательские потоки

### 9.1 Task to verified result

```text
Smart Composer
→ AgentRun snapshot
→ Plan + Chat
→ bounded tool proposal
→ exact Human Request
→ commit
→ verification/evidence
→ Result Report
```

### 9.2 Result to governed memory

```text
evaluated result
→ provenance-backed Memory Candidate
→ user review/edit/approve/reject
→ active MemoryRevision
→ explainable retrieval
→ exact reference in a later Run Context Pack
```

### 9.3 Cross-workspace memory

```text
source grant revision
→ target acceptance
→ source hash-bound acknowledgement
→ active read-only mount
→ source-RLS read
→ target policy and origin-aware reranking
```

Cross-workspace content remains disabled by default and cannot silently enter model context, index, export, derivation или local import.

## 10. Cross-cutting extensions

Первый релиз включает:

- capture profiles как policy-bounded mapping к capture modes;
- repository-owned stable event kinds и per-kind schema versions;
- deterministic read-time upcasters и fail-closed unknown-schema behavior;
- inert signed Run export/import;
- verified inbound webhooks и H8-signed outbound delivery;
- workspace KEK + fresh per-object DEK envelope encryption;
- source-owned grants и target-owned mounts для memory sharing.

Эти concerns расширяют owning Horizons и не создают параллельные runtimes.

## 11. Ошибки и восстановление

Web UI отображает только подтверждённое серверное состояние.

| Ситуация | Нормативное поведение |
|---|---|
| SSE/AG-UI disconnect | `Reconnecting`; resume с последнего durable cursor без повторной команды |
| Provider unavailable | explicit degraded/blocked state; fallback только по policy |
| File changed after proposal | commit denied; reread и новый proposal |
| Stale approval | reject при изменении target/hash/policy/budget/tool revision |
| Possible side effect without confirmed result | `OutcomeUnknown`; reconciliation до retry |
| Server/worker restart | restore journal/checkpoint; reconcile unfinished operations |
| Memory persistence failure | Run result сохраняется; candidate остаётся retryable/pending/failed |
| Shared-memory revoke/purge | future reads deny immediately; persistence quarantined before cleanup |
| H8 unavailable | fail closed; no plaintext fallback |
| Incomplete restore/upgrade | deployment remains fenced/recovery-only |

Public error содержит stable code, safe explanation, разрешённый следующий шаг и correlation ID. Secret values, unrestricted provider responses, hidden reasoning и sensitive content не входят в error DTO, logs или browser telemetry.

## 12. Security and privacy

- Browser получает только public/safe DTOs.
- API keys и decrypted secret values не сохраняются в local/session storage, IndexedDB, URL, logs или error state.
- Все mutations используют idempotency и expected revision, когда применимо.
- H2 authorization выполняется перед protected I/O.
- PostgreSQL forced RLS остаётся вторым isolation layer.
- Artifact preview, Markdown и generative UI используют deny-by-default schema-pinned renderers.
- Mounted memory, webhook content, model output, tools и remote agents являются untrusted data.
- External commitments требуют отдельного H2 gate независимо от происхождения предложения.
- Browser CSP, CSRF/origin, upload/download grant, redaction и cache-control contracts H11/H11B остаются обязательными.

## 13. Responsive, visual and accessibility contract

Web UI сохраняет утверждённый `Structured Depth` visual system:

- Light и Dark themes;
- Comfortable и Compact density;
- desktop: persistent navigation и Inspector;
- tablet: Inspector drawer;
- mobile: detail routes и Plan/Chat tabs;
- WCAG 2.1 AA;
- keyboard-complete navigation;
- focus containment/restoration;
- screen-reader announcements для Run status, streaming updates и Human Requests;
- status, risk и `OutcomeUnknown` не передаются только цветом;
- reduced-motion support;
- bounded virtualization для длинных Runs, memory results и event streams.

## 14. Verification and release gates

Обязательны:

1. Rust unit, integration, property, migration и forced-RLS suites.
2. HTTP, CLI, MCP, SDK, AG-UI и A2A parity tests.
3. React component, router, visual-regression, Playwright и axe suites.
4. Crash/restart tests для Run, approval, tool, webhook, export, encryption и memory-sharing boundaries.
5. Windows 11 + Docker Desktop/WSL2 acceptance.
6. Linux reference CI.
7. Backup в independent store, empty-target restore и recovery validation.
8. Secret/content scan для logs, schemas, exports, metrics и UI persistence.
9. Acceptance suites всех шести follow-up concerns.
10. Release evidence с exact commit, schema, migration, dependency, package и test-result hashes.

Release-blocking vertical slice:

```text
onboarding
→ provider and workspace
→ task
→ Plan + Chat
→ approved file change
→ verification and Result Report
→ Memory Candidate
→ approval in Memory Console
→ memory use in a later Run
→ signed export
→ backup and empty-target restore
```

Team/Embedded, A2A, webhook, encryption и memory-sharing acceptance выполняются отдельными release-blocking scenarios и не обязаны искусственно помещаться в один monolithic end-to-end test.

## 15. Обязательная документация релиза

До начала реализации нужен отдельный integrated implementation plan, который определяет dependency graph, branch/review gates и порядок интеграции всех существующих plans.

До release candidate должны существовать:

- root `README.md` и Windows-first Quick Start;
- versioned configuration reference и safe defaults;
- support matrix;
- threat model и abuse-case matrix;
- public OpenAPI/MCP/AG-UI/A2A schemas и examples;
- Personal, Team и Embedded deployment runbooks;
- migration/upgrade/rollback-compatibility procedure;
- backup/restore/disaster-recovery runbook с RPO/RTO targets;
- operator troubleshooting и incident/fencing procedures;
- human-readable acceptance matrix;
- release checklist, evidence index и known limitations;
- ADR-0002 с conclusive Rig/model-loop decision.

Эти документы могут создаваться вместе с owning implementation tasks, но являются release-blocking artifacts.

## 16. Design completion criteria

Дизайн считается реализованным только когда:

1. все normative plans прошли exit gates;
2. Web UI предоставляет Tasks и полный Memory lifecycle;
3. Personal first-run работает без регистрации;
4. Team и Embedded profiles квалифицированы;
5. Windows primary и Linux reference gates зелёные;
6. Run, tool, memory, Artifact, credential, webhook, export, backup и sharing ownership не дублируется;
7. restart, ambiguous outcomes и stale approvals отображаются правдиво;
8. все шесть follow-up concerns включены и проверены;
9. обязательная документация релиза опубликована;
10. release evidence привязана к точным immutable inputs и test outputs.

## 17. Следующий документ

После отдельного review этого design требуется единый `Vestrace v0.2 Full Product Release Implementation Program`. Он должен ссылаться на существующие detailed plans, а не переписывать их, и разбить работу на bounded reviewable waves с integration gates между ними.
