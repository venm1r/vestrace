# Vestrace v0.2 Migration Ownership Amendment

**Status:** approved documentation correction.

## Purpose

This amendment resolves a migration-number collision discovered while composing the full v0.2 release implementation program.

The approved H11A AG-UI implementation plan reserved migrations `0087`–`0092`. The later State Engine follow-up plans independently reserved a continuous range beginning at `0087` and ending at `0109`. Both ranges cannot be implemented in one forward-only PostgreSQL history.

No migration in either range has been implemented or applied. The repository remains documentation-only, so the collision is corrected before any SQL migration exists.

## Decision

The six State Engine follow-up concerns keep their approved continuous range unchanged:

```text
0087–0088  State capture profiles
0089–0091  Durable event schema compatibility
0092–0095  Signed portable Run export
0096–0099  Webhook extension
0100–0104  Workspace envelope encryption
0105–0109  Cross-workspace memory sharing
```

H11A AG-UI moves to the next free range:

```text
0110  AG-UI endpoints, Run bindings and intake
0111  AG-UI projection snapshots, events and cursors
0112  AG-UI interrupt bindings and resume idempotency
0113  AG-UI frontend-action catalogues
0114  AG-UI schema pins, conformance and release evidence
0115  AG-UI RLS, indexes and cross-resource guards
```

H11B introduces no migration and is unaffected.

## Rationale

Moving H11A is the smallest safe correction:

- one detailed implementation plan changes instead of six;
- the already-normalized State Engine sequence remains contiguous;
- webhook, encryption and memory-sharing dependencies retain their approved ordering;
- H11A remains after H11 and before H11B release qualification;
- no runtime behavior, domain contract, table shape or acceptance scenario changes;
- no applied migration is edited or renumbered.

## Normative precedence

For migration ownership only, this amendment supersedes the original `0087`–`0092` references in:

- `docs/superpowers/plans/2026-07-31-vestrace-h11a-ag-ui-interaction-gateway.md`.

ADR-0004, the H11A roadmap amendment and the rest of the H11A implementation plan remain authoritative for AG-UI behavior.

## Verification gate

Before implementation begins, a repository-owned migration-ownership check must prove:

1. H11 owns only `0081`–`0086`.
2. State Engine extensions own exactly `0087`–`0109`.
3. H11A owns exactly `0110`–`0115`.
4. H11B creates no migration.
5. No migration number has more than one owner.
6. No implementation plan instructs an agent to create an H11A migration in `0087`–`0092`.

## Documentation-only boundary

This amendment authorizes only documentation correction. It does not authorize creating SQL files, applying migrations, implementing H11A or any State Engine extension, starting services or modifying production code.
