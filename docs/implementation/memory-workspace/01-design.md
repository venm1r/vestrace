# 01. Проектные решения и границы

**Статус:** предлагается к принятию. MUST в этом пакете — требование к предлагаемому расширению после его принятия, не утверждение о сегодняшней реализации.

## Выбор подхода

Рассмотрены: отдельный memory-сервис и новая БД; только UI-обёртка над существующими ответами; сквозное расширение текущей канонической модели. Выбран третий путь. Первый создаёт параллельную authority, второй не решает отсутствие содержимого и атомарного редакторского цикла. Используются нынешние crates, PostgreSQL, HTTP, MCP и Console. Отдельный published SDK и новые внешние runtime-интеграции не требуются для первой приёмки.

## Принятые в проекте пакета решения

| ID | Решение | Почему |
|---|---|---|
| MW-D01 | Один memory-first продукт, один канонический writer | Editor и импорт не расходятся в правилах |
| MW-D02 | Новые read/detail/context routes аддитивны | Не сломать старые metadata DTO и If-Match |
| MW-D03 | Correction — новый revision, не UPDATE содержимого прошлого | Восстановление старого текста не уничтожает историю |
| MW-D04 | Source revision неизменяема и отдельна от human correction | Sync не перезаписывает редакторскую правку |
| MW-D05 | Первая версия — один небольшой текстовый документ → одна source-excerpt memory | Нет нестабильного chunk matching или LLM extraction |
| MW-D06 | Preview привязан к сохранённым точным входам и base versions | Подтверждение не разрешает другой файл/состояние |
| MW-D07 | Один item атомарен; batch может завершиться частично | Не держать БД-транзакцию на сотню документов |
| MW-D08 | Background apply через существующий OutboxDispatcher | Нет нового scheduler/lease/retry runtime |
| MW-D09 | Отсутствующий файл — Missing, а не Delete | Не путать потерю доступа с решением уничтожить данные |
| MW-D10 | Source snapshots staging хранятся через существующую material lifecycle | Не создать новый незащищённый content store |
| MW-D11 | Перенос знаний ≠ backup установки и ≠ перенос полномочий | Получатель заново назначает scope/label/доверие |
| MW-D12 | Проверка конкретного feature gate, а не наследование доверия всему проекту | Релиз alpha не закрывает P04/P12/TRUSTED |

## Пользовательские сценарии

UC-01: найти существующую memory, прочитать разрешённое содержимое, увидеть revision и происхождение.  
UC-02: исправить текст, получить durable receipt, увидеть новую revision и старую историю.  
UC-03: импортировать Markdown/plain text/версионированный JSON, проверить preview, подтвердить точный набор.  
UC-04: повторно синхронизировать те же источники; unchanged не создают canonical revisions, изменённые дают новые source versions.  
UC-05: source и manual edit изменились независимо; сохранить всё и разрешить конфликт явно.  
UC-06: собрать разрешённый ContextPack с реальным содержимым и точными citations.  
UC-07: выгрузить выбранный ограниченный набор, перенести его в другой workspace с новыми локальными identity и повторной авторизацией.

## Минимальный интерфейс

Library, Memory Detail, Sources, Import Preview/Progress, Conflict Resolution и Export. Они входят в существующую Console; её дизайн-система сохраняется. Memory Detail не имеет кнопок изменения classification, выдачи capabilities и необратимого purge в обычном сценарии.

## Неотъемлемые границы

Source content — утверждение о том, что было в файле, не доказательство истинности документа. Active — доступность canonical memory в соответствующем runtime, не автоматически Confirmed/Trusted. Confidence отображается как заданная оценка, не вычисленная вероятность истинности. Timestamp файла не создаёт occurred_at автоматически.

Импорт не исполняет Markdown, HTML, JavaScript, инструкции из frontmatter или scripts в JSON. Модель не определяет identity пользователя и scope. Содержимое памяти никогда не монтируется в system instructions как authority.

Повторный импорт после ручной коррекции не меняет memory kind, classification и права под видом синхронизации. Повышение/понижение trust и исправление текста — разные команды.

## Границы первой версии

Один документ до 65 536 UTF-8 bytes; максимум 100 документов и 8 MiB декодированных данных на batch. Форматы `.md`, `.txt`, JSON по поставляемой схеме. Ограничения — выбранный продуктовый envelope, не измеренный предел производительности. Большие документы отклоняются целиком; silent truncation и автоматическое chunking не допускаются.

Нет zip-upload, OCR, PDF parsing, URL crawler, автоматического watcher, remote Git credentials, multisource semantic merge, LLM summaries. Синхронизация запускается явно и сначала показывает preview. Renames связываются только по устойчивому external_id либо явному подтверждённому mapping.

## Отдельное принятие режима выдачи контекста

Byte-only ответ нового endpoint — удобное ограниченное представление памяти, но не эквивалент нормативного hard-token ContextPack. Название URL само по себе не повышает его claim. До включения endpoint требуется явно принять это scope clarification как proposed API extension; ни один существующий потребитель, требующий строгий token bound, не может автоматически переключиться на byte-only. Такой потребитель либо задаёт поддержанный qualified tokenizer, либо получает отказ. Это документированная граница совместимости, а не молчаливое ослабление старой спецификации.
