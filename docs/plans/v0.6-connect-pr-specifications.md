# PR-E1 — ExternalEffectIntent + Adapter Contract

## Goal

Introduce a governed, immutable intent boundary before any external side effect.

## Target model

```text
ExternalEffectIntent
├─ effect_id
├─ execution_ref
├─ actor
├─ adapter/tool
├─ operation
├─ target
├─ normalized arguments digest
├─ expected effect
├─ preconditions[]
├─ risk
├─ reversibility
├─ delivery semantics
├─ idempotency profile
├─ required capability
├─ budget reservation?
└─ created_at
```

## Adapter declarations

Every effect adapter must declare:

```text
DeliverySemantics:
  AT_MOST_ONCE
  AT_LEAST_ONCE
  EFFECTIVELY_ONCE
  UNKNOWN

IdempotencyProfile
ReconciliationMethod
Reversibility
DryRunSupport
CancellationSemantics
Secret/DataDestination policy metadata
```

## Rules

- intent saved before dispatch;
- material intent immutable after authorization;
- agent cannot invent adapter retry/idempotency semantics;
- universal exactly-once claim prohibited.

## Requirements

`EXT-001..005`, `EXT-011`, portions of `EXT-014..018`.

## Acceptance

- effect cannot dispatch without persisted intent;
- adapter with unknown semantics cannot masquerade as effectively-once;
- intent digest changes invalidate approval;
- sensitive arguments persist only redacted/digested/secret-ref form.

# PR-E2 — Effect Dispatch + Receipt + UNKNOWN

## Goal

Implement the critical separation between request attempt, provider acknowledgement and actual outcome.

## Target lifecycle

```text
PREPARED
→ AUTHORIZED
→ DISPATCHING
→ ACKNOWLEDGED / FAILED / UNKNOWN
→ CONFIRMED / RECONCILING / UNKNOWN
```

## ExternalEffectReceipt

Stores provider, dispatch/ack timestamps, response class/digest, external resource/version identifiers, evidence refs and outcome status.

## Critical invariant

```text
attempted ≠ acknowledged ≠ confirmed ≠ desired outcome
```

Timeout/crash after dispatch MUST be able to produce `UNKNOWN`.

## Requirements

`EXT-006..010`, `EXT-016..018`.

## Acceptance

- timeout after possible dispatch does not become FAILED automatically;
- UNKNOWN does not auto-retry unsafe effect;
- provider ACK does not equal business success;
- crash between dispatch and receipt persists/reconstructs ambiguity safely.

# PR-E3 — Reconciliation / Compensation

## Goal

Resolve ambiguous effects using provider-specific evidence and model correction as new effects rather than rollback fiction.

## Reconciliation priority

Use strongest available evidence:

1. idempotency lookup;
2. exact resource/transaction ID;
3. status endpoint;
4. ETag/version/revision;
5. content hash;
6. unique Vestrace marker search;
7. human verification when deterministic evidence unavailable.

## Compensation

```text
original effect A
→ new effect B
→ B compensates A
```

A remains in history.

## Requirements

`EXT-010..015`, supporting execution/effect crash-safety requirements.

## Acceptance

- confirmed duplicate is not dispatched again;
- compensation has its own capability/risk/receipt;
- compensation never deletes/rewrites original effect;
- irreversibility/unknown reversibility triggers stronger policy path;
- stale target precondition yields no dispatch.

# PR-E4 — External-effect Fault Suite / Adapter Qualification

## Goal

Qualify adapters at the failure boundaries that matter for real autonomy.

## Mandatory deterministic fault points

```text
before intent persistence
after intent / before authorization
after authorization / before dispatch
after dispatch / before receipt persistence
after receipt / before outcome confirmation
after outcome / before Run step commit
```

## Adapter qualification matrix

Each adapter must prove/document:

- authorization honored;
- data classification/redaction honored;
- idempotency semantics;
- timeout behavior;
- receipt behavior;
- reconciliation capability;
- cancellation semantics;
- dry-run classification;
- known limitations.

## Requirements

All applicable `EXT-*`, `QUAL-008`, `QUAL-011` foundations.

## AUTONOMY boundary

Per ADR-0010, AUTONOMY crash/fault safety here covers governed execution/repair/effect state across process failure, including safe reconstruction of ambiguous effect state. It does not claim the later TRUSTED incident-containment, TrustState restoration or post-incident revalidation contract.

## Release gate

No high-risk adapter may be enabled as autonomous-safe without the matching fault/semantics evidence.

After E4:

- **v0.6 Connect** may be claimed when its release evidence passes;
- the formal **AUTONOMY** profile may be claimed only if all applicable AUTONOMY dependencies and crash/fault cases pass for the exact qualified target;
- no TRUSTED recovery/revalidation claim is implied.
