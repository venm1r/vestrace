## PR-T1 — Incident + Containment + TrustState

### Requirements

`REC-001..003`, `REC-010`, `REC-017`, `GOV-023`.

### Contract

```text
Incident
├─ incident_id
├─ type
├─ severity
├─ scope
├─ triggering_findings[]
├─ affected_resources[]
├─ status
├─ containment_state
├─ recovery_state
└─ revalidation_state
```

Trust states: `TRUSTED`, `DEGRADED_TRUST`, `UNTRUSTED`, `REVALIDATING`.

Containment actions are governed Run operations: write freeze, capability suspension, workspace isolation, worker pause, external-effect stop, lease revoke, quarantine, read-only mode.

### Acceptance

- critical trust-sensitive finding can open incident;
- containment does not silently create permanent authority;
- process restart never promotes trust.


Results: `PASSED`, `PASSED_WITH_DEGRADATION`, `FAILED`, `INCONCLUSIVE`.

### Trust barrier

```text

→ required RevalidationRun
```


Statuses per requirement: `PASS`, `FAIL`, `NOT_APPLICABLE`, `SKIPPED`, `INCONCLUSIVE`.

### Baseline lifecycle

`QUALIFIED`, `STALE`, `INVALIDATED`, `FAILED`.

Material changes in schema/storage/crypto/policy/adapter/environment can stale/invalidate prior qualification.

### Acceptance

- skipped/inconclusive required MUST fails profile;
- same binary in materially different environment does not inherit qualification automatically;
- signed bundle proves integrity/issuer only, not automatic relying-party trust.

## PR-T8 — TRUSTED Qualification Gate

### Requirements

`QUAL-018` + full TRUSTED dependency closure across applicable `ARC/MEM/TMP/MUT/RET/LRN/CAP/IDW/HLT/EXT/REC/GOV/QUAL`.

### Mandatory suites

```text
memory/temporal/reconciliation
retrieval/context provenance
learning governance
capability/workspace/federation isolation
repair/verification/flapping
external-effect fault/reconciliation
incident/recovery/revalidation
crypto anomaly/key compromise
classification/model-boundary leakage
retention/deletion/export/audit
migration/schema compatibility
```

### Hard gates

- unauthorized disclosure = 0 tolerated;
- unsafe retry of ambiguous irreversible effect = 0;
- TRUSTED transition without revalidation evidence = 0;
- required MUST skipped/inconclusive = profile failure;
- known limitations published.

### v1.0 rule

Vestrace v1.0 may be claimed only for the exact build/config/environment that passes TRUSTED qualification. Federation deployments additionally require FEDERATION dependency closure.
