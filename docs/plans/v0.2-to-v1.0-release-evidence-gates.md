# Vestrace v0.2 → v1.0 — Release Evidence Gates

**Status:** planning baseline  
**Implementation changes authorized:** none  
**Profile claim clarification:** ADR-0010

## Gate principle

A milestone label is earned by evidence, not by feature presence. A milestone label is not automatically a named qualification-profile claim.

```text
implemented
≠ conformance passed
≠ profile qualified
≠ release gate satisfied
```

## v0.2 — Correct

Gate PR: `PR-C8`

Required evidence:

- applicable `ARC/MEM/TMP/MUT/RET` MUST requirements have executable cases;
- profile-scoped `CAP-001`, `CAP-002`, `CAP-014` and `IDW-001..003` protections required by Memory/retrieval pass;
- no required MUST is `SKIPPED` or `INCONCLUSIVE`;
- every `NOT_APPLICABLE` decision has explicit feature/configuration evidence;
- Memory revision/history immutability verified;
- Memory scope cannot widen workspace authority;
- stale mutation/version conflicts rejected;
- Claim conflicts remain explicit;
- current/as-of temporal scenarios pass;
- ContextPack exact-revision provenance and hard budget pass;
- workspace isolation negative tests pass;
- derived retrieval state rebuild equivalence passes;
- migration-from-baseline fixture preserves history.

`RET-014` may be `NOT_APPLICABLE` only when the qualified target exposes no mounted cross-workspace retrieval.

Claim allowed after gate: **CORE + MEMORY qualified for the exact tested target**.

## v0.3 — Learn

Gate PR: `PR-L3`

Required evidence:

- evaluation facts retain exact target/evaluator/evidence refs;
- raw evaluation facts survive learned-projection changes;
- model-judge signals cannot silently become authoritative;
- learning cannot self-escalate capability/policy authority;
- cognition benchmarks cover temporal recall, contradictions, provenance, forgetting and cross-session continuity;
- quality metrics are reported separately from hard gates.

Claim allowed: **COGNITION qualified for the exact tested target** when its dependency closure remains valid.

## v0.4 — Govern

Gate PR: `PR-G6`

Required evidence:

- default deny verified;
- missing/expired/revoked capability denied;
- child authority never exceeds parent;
- approval cannot override hard deny/budget/capability ceiling;
- every exposed HTTP/MCP/CLI/worker/internal governed path uses common authorization semantics;
- workspace cross-read negative suite passes;
- source grant + target mount required for sharing;
- revoked/stale mount denies future content;
- mounted retrieval satisfies `RET-014`;
- federation identity/trust alone cannot authorize disclosure.

Claim allowed: **v0.4 Govern** for the tested configuration. The formal **FEDERATION** profile may additionally be claimed only when the enabled federation configuration has complete applicable federation/profile evidence closure, including remote evidence checks required by the qualification contract.

## v0.5 — Understand

Gate PR: `PR-H5`

Required evidence:

- HealthFinding carries invariant/scope/evidence/severity/repairability;
- `UNKNOWN != HEALTHY`;
- deterministic repair only moves downward in authority hierarchy;
- stale RepairPlan never mutates state;
- RepairExecution success does not close finding without verification;
- flapping/attempt budgets stop infinite repair loops;
- suppression/accepted risk do not erase raw finding truth;
- doctor is read-only; repair execution is explicit and governed.

Claim allowed: **v0.5 Understand health/integrity/repair contract conformance for the tested scope**. `Understand` is a milestone label, not a separate named qualification profile.

## v0.6 — Connect

Gate PR: `PR-E4`

Required evidence:

- every effect adapter declares delivery/idempotency/reconciliation/reversibility semantics;
- intent persisted before dispatch;
- timeout/crash after dispatch can produce `UNKNOWN`;
- `UNKNOWN` is never auto-converted to `FAILED`;
- unsafe retry after ambiguous irreversible effect is blocked;
- stale approved intent fails before dispatch;
- receipts preserve effect evidence without secret plaintext;
- compensation is a distinct new effect linked to original;
- deterministic fault suite covers dispatch/receipt persistence boundaries;
- execution/effect crash state is safely preserved or reconstructed according to ADR-0010.

Claim allowed: **v0.6 Connect** for included qualified adapters. The formal **AUTONOMY** profile may be claimed only when all applicable AUTONOMY dependencies and crash/fault requirements pass for the exact target. This does not claim TRUSTED incident/revalidation semantics.

## v1.0 — Trust

Gate PR: `PR-T8`

Required evidence:

- all lower required profile gates remain valid/not stale;
- incident containment/recovery/revalidation scenarios pass;
- `UNTRUSTED → TRUSTED` requires successful required revalidation;
- snapshot/replay/rebuild recovery preserves canonical history;
- secret plaintext is excluded from ordinary Memory/log/receipt paths;
- classification lineage and model/provider destination restrictions pass;
- retention/hold/deletion verification semantics pass;
- governed export/audit integrity requirements pass;
- QualificationBundle identifies exact source/build/config/environment/suite;
- material baseline changes invalidate/stale qualification;
- known limitations are present;
- all TRUSTED hard gates pass with zero skipped/inconclusive required MUSTs.

Claim allowed: **TRUSTED** for the exact qualified build/configuration/environment. Federation deployments additionally require full FEDERATION closure and may claim **TRUSTED-FEDERATED** only when that closure passes.

## ReleaseEvidence manifest

Every milestone release should reference:

```text
version
source_revision
build_digest
schema_versions
milestone_label
claimed_profiles
qualification_bundle_refs
applicability_decisions
known_limitations
migration_baseline
supported adapters/backends
```

No document or release note may claim a stronger guarantee than its evidence bundle supports.
