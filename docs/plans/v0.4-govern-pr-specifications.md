# PR-G1 — CapabilityGrant / PolicyDecision Kernel

## Goal

Replace coarse capability presence checks with durable constrained runtime authority.

## Target model

```text
CapabilityGrant
├─ grant_id
├─ issuer
├─ subject
├─ operation/tool selector
├─ resource selector
├─ valid_from / valid_until
├─ budget constraints
├─ risk ceiling
├─ conditions[]
├─ obligations[]
├─ delegation policy
└─ lifecycle state
```

```text
PolicyDecision
├─ decision_id
├─ exact policy/version
├─ subject
├─ operation/resource
├─ input_state_ref
├─ effective risk
├─ result
├─ obligations[]
└─ evidence
```

Decision results:

```text
DENY
ALLOW
PREPARE_ONLY
REQUIRE_APPROVAL
```

## Migration

Preserve existing capability/policy schema as legacy or issuance source. New authority tables are additive. Existing role/capability enums are not silently interpreted as unconstrained permanent grants.

## Requirements

`CAP-001..004`, `CAP-008..013`.

## Acceptance

- default deny;
- expiry enforced;
- resource/operation/risk/budget restrictions effective;
- PolicyDecision records exact version/input state;
- approval cannot override hard deny/budget/capability ceiling.

# PR-G2 — Universal Authorization Boundary

## Goal

Ensure every governed entry point evaluates the same application-level authority contract.

## Surfaces

```text
HTTP
MCP
worker/background jobs
internal application commands
replay/recovery side-effect paths
future federation adapters
```

## Rules

- no surface receives implicit trust because it is internal;
- RLS remains defense-in-depth, not the only authorization layer;
- local-trusted/dev bypass must be explicit, configuration-scoped and declared as a limitation;
- protected operations must fail closed if authority cannot be evaluated.

## Requirements

`CAP-001..014`, supporting `IDW-001..003`.

## Acceptance

A policy-bypass matrix proves equivalent deny behavior across all exposed paths.

# PR-G3 — Delegation Attenuation + Hierarchical Budgets

## Goal

Make subagent delegation least-privilege and auditable.

## Rule

```text
child authority =
parent effective authority
∩ explicit delegated subset
∩ child constraints
∩ current policy
```

Default max delegation depth: `1` unless policy explicitly raises it.

## Budget model

Child allocations are bounded subsets and account against parent/global limits according to typed accounting policy.

Budget dimensions may include:

- steps/time;
- tokens/cost;
- effect count/rate;
- artifact bytes;
- subruns;
- high-risk operations.

## Requirements

`CAP-005..007`, `CAP-013`.

## Acceptance

- child cannot widen operation/resource/risk/validity;
- depth limit enforced;
- budget cannot be double-spent under concurrency;
- delegation chain remains auditable;
- context delegation does not imply authority delegation.

# PR-G4 — Cross-workspace Sharing v2

## Goal

Normalize current one-sided cross-workspace grant foundations into the target `Grant + Mount` model.

## Target chain

```text
source workspace
→ MemoryShareGrant
→ immutable grant revision
→ target acceptance
→ MemoryMount
→ SharedMemoryRef
```

## Hard rules

- exact source + exact target;
- no wildcard target;
- no implicit transitive sharing;
- read-only mount by default;
- separate discover/read/context/model-use/derive/export permissions;
- source and target policy checks both required;
- revoke/suspend/expire/stale states explicit.

## Legacy migration

Existing simple cross-workspace grant rows are preserved as legacy source-side proposals/references. They MUST NOT automatically become active mounts. Target acceptance is required.

## Requirements

`IDW-004..014` and `RET-014` once mounted retrieval is enabled.

## Acceptance

- target cannot access before acceptance;
- revocation blocks future content access;
- every governed mounted retrieval evaluates source and target policy;
- mount-of-mount/re-share denied by default;
- local import creates new local Memory with source provenance;
- RLS workspace isolation remains enabled.

# PR-G5 — Federation Trust Boundary

## Goal

Allow remote/federated identities and qualification evidence without importing remote permissions as local authority.

## Target model

Remote peer may present:

- identity/installation signature;
- capability manifest;
- qualification evidence;
- crypto/governance profile.

Local policy decides what is recognized.

## Rules

```text
remote identity recognized
!=
remote data authorized
!=
remote capability imported
```

Every remote operation receives locally computed effective authority.

## Requirements

`IDW-012`, governance/federation portions of `GOV-*` and `QUAL-017` foundation.

## Acceptance

- self-asserted TRUSTED status insufficient;
- remote capability cannot become local capability automatically;
- data disclosure independently checks classification/purpose/recipient;
- unknown/untrusted signer fails closed for protected operations;
- formal FEDERATION qualification cannot be inferred from feature enablement alone.

# PR-G6 — Govern / Federation Conformance Gate

## Goal

Turn authority and isolation guarantees into hard-gate evidence.

## Mandatory negative suites

```text
expired capability denied
revoked capability denied
child escalation denied
approval for modified intent invalid
workspace A cannot read/write B
wildcard/transitive sharing denied
target without mount acceptance denied
mounted retrieval source+target policy enforced
read permission does not imply export/model-use
admin does not imply federation-global authority
alternate HTTP/MCP/worker path cannot bypass policy
```

## Release gate

No security/governance hard gate may be skipped or compensated by a score.

After G6:

- **v0.4 Govern** may be claimed for the qualified configuration;
- formal **FEDERATION** may be claimed only where federation is enabled and the complete applicable FEDERATION/profile dependency evidence closure passes;
- otherwise the release claim remains limited to the governed federation boundary behavior actually evidenced.
