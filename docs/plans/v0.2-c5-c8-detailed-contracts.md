**Status:** approved documentation plan

## PR-C5 — Retrieval Exact-revision Hydration and Authorization Boundary

### Requirement mapping

| Requirement | Planned evidence |
|---|---|
| RET-001 | authorization/classification filtering precedes content disclosure |
| RET-002 | current retrieval excludes superseded/expired cognition |
| RET-003 | unresolved conflict remains explicit |
| RET-005 | every item retains source/revision provenance |
| RET-006 | every item retains inclusion explanation |
| RET-007 | provider/destination classification policy preserved |
| RET-008 | inclusion does not raise authority |
| RET-013 | representation retains original revision ref |
| RET-015 | retrieval run records policy/version/degradation metadata |
| CAP-001 | Memory/retrieval authorization is based on effective capability/policy, not role name |
| CAP-002 | protected Memory/retrieval paths fail closed by default |
| CAP-014 | agent-facing Memory/retrieval APIs expose no self-escalation path |
| IDW-001..003 | workspace/actor isolation is enforced independently from object identity |

`RET-014` is a future applicability handoff: C5 must provide a policy hook that can evaluate source/target sharing context, but the normative mounted-content requirement becomes applicable when `MemoryMount` exists/enables governed mounted retrieval in G4.

### Pipeline contract

```text
query
→ candidate identity search
→ workspace/capability/share/classification filter
→ exact canonical revision hydration
→ temporal applicability
→ claim/conflict state
→ representation candidate
→ assembly
```

Candidate explanation/ranking metadata is never canonical content.

### Authorization scope

C5 closes the **minimum Memory/retrieval security boundary required by CORE+MEMORY**. It does not implement the full constrained `CapabilityGrant`, delegation, risk and universal entry-point model; those are completed by G1-G3.

### Journal contract

Future retrieval journal should record at least:

```text
request/query identity
temporal perspective
candidate refs
included exact revision refs
policy/version refs
classification decision
degradation/warnings
retrieval generations
```

### Exit gate

For every ContextPack item the exact authorized canonical revision must be reproducible from the journal/provenance chain, and forbidden workspace/capability content must not be disclosed downstream.

## PR-C6 — ContextPack 2.0 Representation / Section Assembly

### Requirement mapping

| Requirement | Planned evidence |
|---|---|
| RET-004 | hard token/content budget never exceeded |
| RET-005 | provenance survives all representation levels |
| RET-006 | inclusion explanation remains available |
| RET-008 | compression/inclusion never raises authority |
| RET-013 | Full/Summary/Atomic/Reference preserve source ref |
| ARC-010 | ContextPack remains a projection |

### Section contract

Canonical section classes:

```text
constraints
current_facts
critical_decisions
open_tasks
procedures
conflicts_warnings
supporting_details
recent_events
history
```

Section assignment is deterministic from item semantics/type where possible; model-assisted classification cannot become source authority.

### Representation contract

```text
FULL      exact authorized content within limits
SUMMARY   governed derivative + source revision
ATOMIC    minimal proposition/fact derivative + source revision
REFERENCE content-free/limited reference sufficient for later governed expansion
```

Representation fallback order is explicit and budget-driven. Arbitrary string truncation is not a valid `REFERENCE` implementation.

### Budget contract

Assembly must reserve space for mandatory constraints/warnings before optional supporting detail. Overflow causes representation downgrade/exclusion, never hard-budget violation.

### Exit gate

A fixed input state produces deterministic section/representation/budget results under the deterministic core contract. `CONF-RET-001` remains the stable hard-budget case registered by PR-0.1.

## PR-C7 — Temporal Retrieval + Multi-channel Wiring

### Requirement mapping

| Requirement | Planned evidence |
|---|---|
| TMP-004 | current query excludes non-current cognition |
| TMP-005 | as-of query reconstructs historical semantics |
| RET-009 | safe channel failure yields explicit degraded mode |
| RET-010 | absence of safe fallback fails closed |
| RET-011 | incomparable channel scores use rank fusion |
| RET-012 | relevant state/policy/share/classification changes invalidate cache |
| RET-015 | degradation/channel decisions journaled |

### Temporal modes

```text
CURRENT
KNOWN_AS_OF(t)
VALID_AS_OF(t)
RECONSTRUCTED_AS_OF(t)
TIMELINE
ALL_HISTORY
```

Each request has one explicit temporal perspective. API may provide convenience defaults, but persisted/journaled execution records the resolved mode.

### Channel contract

```text
exact
structured
full_text
vector
```

Optional future channels may be added, but no channel owns truth. Each returns candidate refs + channel-local evidence/rank.

### Fusion contract

RRF is the default for heterogeneous rank channels. Direct arithmetic summation of incomparable score spaces is prohibited without a separately qualified normalization contract.

### Degradation matrix

- vector unavailable + structured/full-text safe -> degraded result with warning;
- all semantic candidate channels unavailable -> fail closed;
- stale index generation -> exclude/rebuild/fallback according to authority, never silently trust stale projection;
- canonical hydration failure for candidate -> item excluded + diagnostic evidence.

### Exit gate

Temporal semantics remain correct even if all derived/vector indexes are deleted and rebuilt.

## PR-C8 — CORE + MEMORY Conformance Gate

### Requirement scope

Required families/scope:

```text
ARC applicable CORE laws
MEM all applicable v0.2 MEMORY MUSTs
TMP all applicable MUSTs
MUT all applicable MUSTs
RET all applicable MUSTs
CAP-001, CAP-002, CAP-014 for protected Memory/retrieval surfaces
IDW-001..003 for workspace/actor isolation on those surfaces
```

`RET-014` is `NOT_APPLICABLE` at C8 only when the qualified configuration exposes no `MemoryMount` or equivalent mounted cross-workspace retrieval. Applicability must be evidenced; the feature becoming enabled later makes the requirement mandatory.

### Conformance-case minimum set

```text
CONF-CORE-001 optimistic version conflict is rejected
CONF-ARC-001 derived state cannot overwrite canonical state
CONF-MEM-001 immutable Memory revision/history
CONF-MEM-002 active Memory has admissible evidence
CONF-MEM-003 claim conflict remains explicit
CONF-MEM-004 scope cannot widen workspace authority
CONF-TMP-001 occurred/recorded/validity axes differ
CONF-MUT-001 correction/mutation evidence exists
CONF-MUT-002 correction appends history
CONF-RET-001 hard ContextPack budget
CONF-RET-002 authorization before disclosure
CONF-RET-003 exact revision hydration
CONF-RET-007/008 current/as-of reconstruction distinction
CONF-RET-009 degraded channel behavior
CONF-CAP-001 missing Memory/retrieval capability fails closed
CONF-CAP-013 agent-facing Memory/retrieval path cannot self-escalate
CONF-IDW-001 foreign workspace read denied
CONF-IDW-009 actor identity does not imply authority
```

### Migration fixture contract

Qualification fixture starts from a database representing the current pre-C1 implementation baseline, applies forward migrations, and verifies:

- existing Memory/event history preserved;
- unknown times/actors are not fabricated;
- old provenance remains addressable;
- RLS remains enabled;
- existing scope metadata is not reinterpreted as broader authority;
- derived indexes rebuild;
- new invariants hold or produce explicit migration findings/limitations.

### Profile-evaluation rules

Applicable required MUST execution statuses:

```text
PASS -> acceptable
FAIL -> profile fails
SKIPPED -> profile fails
BLOCKED -> profile incomplete/fails until resolved
INCONCLUSIVE -> profile fails
```

`NOT_APPLICABLE` is a separate evidence-backed applicability decision, not a test execution status. It maps to the qualification requirement result only when target/configuration evidence proves the obligation is inapplicable.

### Release evidence

C8 produces a CORE+MEMORY conformance evidence set, not a full CAP/IDW governance, AUTONOMY, FEDERATION or TRUSTED claim.

Minimum evidence:

```text
source revision
build identity
migration set
suite version
requirement results
scenario evidence
applicability decisions
known limitations
```

### Exit gate

`v0.2 Correct` may be claimed only when every required CORE+MEMORY MUST and the profile-scoped foundational security/isolation obligations have an executable verification path and pass for the declared build/environment scope.
