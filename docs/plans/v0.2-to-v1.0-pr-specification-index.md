## Review rule for every future PR

Every future implementation PR must answer:

1. Which normative requirement IDs does it target?
2. Which authoritative state owner changes?
3. What forward-only migration/backfill is required?
4. What happens under stale state, crash, retry or ambiguity?
5. What security/data-governance boundary changes?
6. What executable evidence proves the requirements?
7. What current-implementation documentation must be updated?

## Documentation-only rule

These files are implementation specifications, not implementation commits. No Rust code, migrations, runtime configuration, HTTP behavior or MCP behavior is changed by this documentation branch.
