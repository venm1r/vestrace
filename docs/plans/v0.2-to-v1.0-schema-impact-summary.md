## Rules

1. Never edit applied migrations.
2. Never allocate concrete migration numbers in architecture docs.
3. Add RLS/ownership with new tenant-scoped tables from day one.
4. Backfills are deterministic, restartable and bounded.
5. Unknown historical values remain unknown.
6. No backfill fabricates actor, policy, trust, evidence authority, semantic truth or external-effect outcome.
7. Derived-state migrations may rebuild; canonical history migrations preserve history.
8. Compatibility read paths may remain temporarily, but new authoritative writes must target the new model once cut over.
9. Cleanup/drop migrations happen only after conformance evidence proves no dependency on legacy structures.
10. Schema version changes that affect trust/profile semantics can stale/invalidate qualification baselines.

## Highest-risk migrations

| Area | Risk | Required protection |
|---|---|---|
| Claims from legacy Memory | semantic fabrication | no blind conversion; deterministic/proposal-only |
| Capability migration | privilege widening | fail-closed; no implicit broad grants |
| Cross-workspace grants | unauthorized disclosure | no auto-mount; target acceptance required |
| External effects | false outcome history | no historical CONFIRMED synthesis from transport success |
| Trust state | false assurance | never backfill TRUSTED from uptime/tests |
| Secret/key handling | plaintext duplication | refs only; external key/secret provider |
| Deletion | false erasure claim | explicit semantics + verification |
| Qualification | false certification | exact build/config/environment identity |
