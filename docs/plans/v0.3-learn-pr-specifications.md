# PR-L1 — Evaluation Fact v2

## Goal

Turn the current generic evaluation CRUD foundation into evidence-backed evaluation facts that can safely support learning.

## Target model

```text
Evaluation
├─ evaluation_id
├─ target_execution_ref
├─ evaluator_kind
├─ metric_or_check_kind
├─ result / score
├─ evidence_refs[]
├─ evaluator_revision?
├─ policy_version?
├─ created_by
└─ created_at
```

Evaluator kinds:

```text
DETERMINISTIC
HUMAN
HEURISTIC
MODEL_JUDGE
```

Authority is determined by policy and evidence, not enum name alone.

## Compatibility

Existing evaluation records are preserved. Historical rows lacking exact target/evaluator provenance remain legacy/partial evidence rather than receiving fabricated authority.

## Requirements

`LRN-001`, `LRN-002`, `LRN-006..008`.

## Acceptance

- every new evaluation points to exact execution/revision target;
- raw evaluation survives learned projection deletion;
- model-judge result is distinguishable from human/deterministic evidence;
- evidence refs and evaluator revision are reproducible;
- legacy rows remain readable without invented provenance.

# PR-L2 — Learned Projection / Proposal Boundary

## Goal

Allow Vestrace to derive useful learned conclusions without silently self-modifying authoritative cognition, agents, workflows or permissions.

## Target split

```text
raw execution/evaluation evidence
        ↓
LearnedProjection
        ↓
ChangeProposal
        ↓
policy / verification / approval
        ↓
new canonical revision
```

LearnedProjection examples:

- model/tool performance summary;
- preferred routing recommendation;
- recurring user preference candidate;
- agent/skill improvement suggestion.

## Hard restrictions

Learning MUST NOT automatically:

- grant/revoke capabilities;
- alter security policy;
- mutate an Agent/Skill/Workflow revision in place;
- overwrite canonical Memory/Claim;
- treat model-judge output as authoritative truth.

## Requirements

`LRN-002..005`, `LRN-007..008`.

## Acceptance

- projection links raw evidence;
- proposal has exact target version;
- stale target proposal is rejected/rebased explicitly;
- accepted proposal creates new version, never in-place mutation;
- rejected proposal leaves raw evidence intact;
- security/capability changes cannot be auto-applied by learning.

# PR-L3 — COGNITION Benchmark / Conformance Gate

## Goal

Qualify the learning/cognition layer using property-oriented scenarios rather than exact LLM wording.

## Benchmark families

```text
Recall
Temporal Recall
Contradiction Resolution
Provenance
Long-Horizon Memory
Context Selection
Cross-Session Continuity
Forgetting
Access Isolation
Shared Cognition (where applicable later)
```

## Metrics

Candidate metrics:

- Recall@k;
- Precision@k;
- MRR;
- provenance coverage;
- stale-memory rate;
- conflict-masking rate;
- context utilization.

Security leakage remains a hard gate, not an average metric.

## Requirements

All applicable `LRN-*` plus inherited `CORE + MEMORY` hard gates.

## Acceptance

```text
[ ] raw vs learned state separation verified
[ ] target/evaluator provenance complete for new evaluations
[ ] learning cannot alter authority directly
[ ] asset changes are versioned/proposed
[ ] benchmark data and expected properties are versioned
[ ] exact LLM wording is not a pass condition
[ ] security/provenance hard gates remain zero-tolerance
```

Only after this gate may **v0.3 Learn / COGNITION** be claimed.
