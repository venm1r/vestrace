# v0.4 Govern — Migration / Conformance Matrix (G1–G6)

**Status:** documentation-only implementation contract

## G1 — CapabilityGrant / PolicyDecision Kernel

### Migration

Add durable capability grants, lifecycle state, typed selectors/constraints, policy decisions and approval-intent binding.

Backfill rules:

- existing role/capability hints are not auto-promoted to unrestricted grants;
- only deterministic current permissions become explicit bounded grants;
- uncertain legacy permissions remain unresolved/disabled until reviewed;
- policy version references are exact for all new decisions.

### Cases

| Case | Requirements | Expected result |
|---|---|---|
| CONF-CAP-001 Default deny | CAP-002 | no matching effective capability → DENY |
| CONF-CAP-002 Expiry | CAP-004 | expired grant rejected |
| CONF-CAP-003 Constraint enforcement | CAP-003 | resource/operation/time/budget/risk/condition all constrain allow |
| CONF-CAP-004 Approval binding | CAP-010..012 | material intent change invalidates approval |
| CONF-CAP-005 Policy evidence | CAP-011 | decision stores exact policy version/input state |

## G2 — Universal Authorization Boundary

### Migration

No semantic data backfill required; may add audit/decision correlation storage.

Every governed entry point routes through the same application authorization boundary:

```text
HTTP / MCP / CLI / worker / recovery / internal command
→ effective authority decision
→ operation
```

### Cases

| Case | Requirements | Expected result |
|---|---|---|
| CONF-CAP-006 Surface parity | CAP-001, CAP-014 | forbidden operation denied through every exposed surface |
| CONF-IDW-001 Workspace isolation | IDW-001..003 | foreign workspace data denied even with guessed UUID |
| CONF-CAP-007 No internal bypass | CAP-014 | worker/replay path cannot skip authorization when operation is governed |

## G4 — Cross-workspace Sharing v2

### Migration

Target schema:

```text
MemoryShareGrant
MemoryShareGrantRevision
MemoryMount
SharedMemoryRef
```

Legacy cross-workspace grants:

- preserve as historical records;
- do not auto-activate target access;
- convert to proposal/pending acceptance only when exact source/target and scope are provable;
- require target-side acceptance for active mount;
- no wildcard/transitive migration.

### Cases

| Case | Requirements | Expected result |
|---|---|---|
| CONF-IDW-002 Two-sided consent | IDW-004 | source grant without target mount cannot disclose content |
| CONF-IDW-003 No wildcard | IDW-005 | wildcard target rejected |
| CONF-IDW-004 No transitive sharing | IDW-006 | mounted content cannot be re-shared by default |
| CONF-IDW-005 Source+target checks | IDW-007 | both policy boundaries independently enforced |
| CONF-IDW-006 Revocation | IDW-008/013 | future reads denied; historical disclosure audit preserved |
| CONF-IDW-007 Namespaced ref | IDW-009/010 | shared ref cannot masquerade as local MemoryId |
| CONF-IDW-008 Derivation provenance | IDW-011 | local derivative/import retains exact source provenance |

## G5 — Federation Trust Boundary

### Schema

Add remote/federated principal identity, federation relationship/trust evidence, remote qualification references and local policy decisions.

No remote permission is imported as local capability.

### Cases

| Case | Requirements | Expected result |
|---|---|---|
| CONF-FED-001 Trust != data permission | IDW-012 | trusted remote identity alone cannot read/export data |
| CONF-FED-002 Local authority | CAP-001, IDW-012 | remote principal receives locally evaluated bounded capability only |
| CONF-FED-003 Self-asserted trust | QUAL-017 | remote `TRUSTED` claim without accepted evidence is insufficient |
| CONF-FED-004 RLS intact | IDW-014 | federation path does not disable workspace isolation |

## G6 — Govern / Federation Gate

Required negative suites:

1. expired/revoked capability;
2. role name without capability;
3. child escalation;
4. modified approved intent;
5. workspace UUID guessing;
6. HTTP/MCP/worker policy bypass;
7. source grant without target acceptance;
8. revoked/stale mount;
9. transitive share attempt;
10. federation trust without data permission;
11. restricted-data provider/export use without governance allow.

Gate:

```text
required CAP MUST PASS
required IDW MUST PASS
security bypass = 0
cross-workspace leakage = 0
required SKIPPED/INCONCLUSIVE = 0
```

## Global migration rules

1. Legacy broad permissions are never widened during migration.
2. Uncertain authority migrates fail-closed.
3. Role assignments may seed grant proposals, not unconditional effective authority.
4. Old cross-workspace grants do not become accepted mounts automatically.
5. Revocation/history audit remains append-oriented.
6. RLS is retained throughout all federation/sharing transitions.
