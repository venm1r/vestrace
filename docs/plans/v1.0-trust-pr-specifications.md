# PR-T1 — Incident + Containment + TrustState

## Goal

Introduce coordinated incident response and scope-specific trust without conflating health, availability and permission.

## Target model

```text
Incident
├─ incident_id
├─ type / severity
├─ scope
├─ triggering_findings[]
├─ affected_resources[]
├─ status
├─ containment_state
├─ recovery_state
└─ revalidation_state
```

Lifecycle:

```text
OPEN
→ CONTAINING
→ CONTAINED
→ RECOVERING
→ REVALIDATING
→ RESOLVED
→ CLOSED
```

Trust states:

```text
TRUSTED
DEGRADED_TRUST
UNTRUSTED
REVALIDATING
```

## Containment

May freeze writes, suspend capabilities, isolate workspace/domain, pause workers/effects, revoke leases or force read-only. Containment should minimize blast radius.

## Requirements

`REC-001..003`, trust portions of `REC-010` and `REC-017`.

## Acceptance

- finding can exist without Incident;
- one Incident groups several findings;
- process running does not imply TRUSTED;
- containment actions are capability/policy audited;
- partial workspace/domain trust is representable.

# PR-T2 — Recovery Classification + RevalidationRun

## Goal

Extend existing Run recovery into a cross-domain evidence-backed trust restoration protocol.

## Startup/recovery classification

```text
SAFE_TO_RESUME
SAFE_TO_RETRY
MUST_RECONCILE
MUST_ABORT
HUMAN_REQUIRED
```

Apply to unfinished Runs, repairs, effects, leases and workflows according to their typed recovery profile.

## RevalidationRun

```text
RevalidationRun
├─ run_id
├─ incident_id?
├─ scope
├─ level
├─ baseline_state_ref
├─ checks[]
├─ evidence_refs[]
├─ result
└─ completed_at
```

Levels:

```text
LOCAL DOMAIN WORKSPACE INSTALLATION FULL_TRUST
```

Results:

```text
PASSED
PASSED_WITH_DEGRADATION
FAILED
INCONCLUSIVE
```

## Trust barrier

```text
Recovery complete
→ required RevalidationRun passes
→ policy evaluates evidence
→ trust transition
→ capabilities restored progressively
```

## Requirements

`REC-004..018` applicable set.

## Acceptance

- resume-all impossible;
- UNKNOWN external effect becomes MUST_RECONCILE;
- ambiguous irreversible effect never auto-retries;
- INCONCLUSIVE cannot produce TRUSTED;
- divergent histories do not latest-win;
- recovery loop budget stops repeated failure;
- forensic evidence preserved before destructive recovery.

# PR-T3 — SecretRef / KeyProvider / Key Lifecycle

## Goal

Normalize crypto/key seeds into explicit secret and key boundaries.

## Secret rule

Secret plaintext is never ordinary Memory or durable ContextPack content.

```text
SecretRef
→ authorization
→ SecretBackend/KeyProvider resolve
→ ephemeral use
→ discard plaintext
```

## Key lifecycle

```text
ACTIVE
ROTATING
RETIRED
REVOKED
DESTROYED
```

Metadata stores provider/key/version/purpose/scope/algorithm but not ordinary DB plaintext private material.

## Encryption model

Use provider abstraction and envelope encryption for applicable large/CAS objects:

```text
object → DEK → wrapped by workspace/purpose KEK
```

Algorithm/version metadata must be agile.

## Requirements

`GOV-001`, `GOV-005..010`, `GOV-023` foundations.

## Acceptance

- secret cannot be persisted as Memory by normal secret flow;
- logs/receipts do not contain secret plaintext;
- revoked key cannot be used as active key;
- historical crypto metadata identifies exact key/algorithm version;
- key compromise opens trust-sensitive finding/incident path.

# PR-T4 — DataPolicy / Classification Lineage / Model Boundary

## Goal

Make data handling policy independent of capability and enforce it at derived/model/provider boundaries.

## Classification

```text
PUBLIC < INTERNAL < CONFIDENTIAL < RESTRICTED
```

Derived content cannot automatically lower source sensitivity.

## DataPolicy

Controls classification, purpose, provider/model destination, residency, sharing, retention/export/deletion constraints.

Authorization requires both:

```text
Capability ALLOW
∩ DataPolicy ALLOW
```

## Model boundary

```text
ContextPack
→ effective classification
→ destination/locality eligibility
→ purpose
→ redaction/minimization
→ invocation
```

## Requirements

`GOV-001..004`, `GOV-011..012`, `GOV-020..025` applicable set.

## Acceptance

- RESTRICTED data cannot reach forbidden provider through direct/cache/summary/fallback paths;
- read permission does not imply model-use/export permission;
- declassification is explicit/provenanced;
- policy decision stores exact policy version;
- new policy does not rewrite history of old decision.

# PR-T5 — Retention / Hold / Dependency-aware Deletion Verification

## Goal

Replace simple hard-purge semantics with a complete governed data lifecycle.

## Retention lifecycle

```text
ACTIVE
→ EXPIRED
→ PENDING_DISPOSAL
→ DISPOSED
```

Retention trigger is explicit.

## DataHold

Has exact scope, authority, reason, timestamps and policy reference.

## Deletion semantics

```text
LOGICAL_DELETE
PHYSICAL_DELETE
CRYPTO_ERASURE
```

These must not be conflated.

## Dependency-aware deletion

Deletion planner traverses:

```text
source
→ claims/memories/derivations
→ indexes/caches/summaries
→ artifacts
→ exports/shares
→ backup constraints
```

Deleting sole admissible evidence triggers Claim revalidation.

## Verification

```text
DeletionPlan
→ Execution
→ DeletionVerification
```

Successful SQL DELETE alone is insufficient for broader disposal claims.

## Requirements

`GOV-013..017`, `GOV-026`.

## Acceptance

- hold blocks disposal;
- physical delete does not claim backup eradication;
- crypto erasure and physical erasure reported separately;
- deleted evidence invalidates/revalidates dependents;
- remaining backup copies and expiry are reported honestly.

# PR-T6 — Governed Export / Audit Integrity

## Goal

Make exports portable, policy-bound and verifiable; make critical audit history tamper-evident.

## DataExportPlan

Includes exact scope, purpose, recipient, revisions, classifications, redactions, encryption/signing, expiry and policy/capability/approval refs.

## ExportBundle

```text
manifest
schema versions
objects/references
provenance
classification
hashes
signature?
encryption metadata
```

Authority does not transfer with exported data.

## Audit integrity

Critical profile uses chained digests and optional signed checkpoints.

Hash integrity, signature authenticity and authorization remain distinct.

## Requirements

`GOV-009..010`, `GOV-018..019`, related `GOV-024..025`.

## Acceptance

- unauthorized/over-classification export denied;
- manifest identifies exact revisions/policy;
- export signature verifies integrity/issuer only, not permission/truth;
- audit chain tampering detected;
- audit payload contains no secret plaintext.

# PR-T7 — QualificationBundle / Baseline Lifecycle

## Goal

Implement full profile qualification evidence for exact build/config/environment.

## QualificationBundle

```text
qualification_id
target manifest
source revision
build digest
configuration digest
environment manifest
profile
suite version
requirement results
scenario results
metrics
failures/skipped

evidence refs

signature?
```

Result states per requirement:

```text
PASS
FAIL
NOT_APPLICABLE
SKIPPED
INCONCLUSIVE
```

Required MUST + SKIPPED/INCONCLUSIVE means profile not qualified.

## Baseline lifecycle

```text
QUALIFIED
STALE
INVALIDATED
FAILED
```

Material backend/provider/policy/crypto/schema changes may stale/invalidate prior qualification.

## Requirements

`QUAL-001..007`, `QUAL-011..015`, `QUAL-017`.

## Acceptance

- bundle identifies exact target environment;
- qualification is not inferred from CI green;
- known limitations required;
- material configuration drift changes baseline status;
- signature does not automatically make remote bundle trusted.

# PR-T8 — TRUSTED Qualification Gate

## Goal

Prove the complete Trust Contract for the supported target configuration.

## Required inherited suites

```text
CORE
MEMORY
COGNITION
AUTONOMY
GOVERNANCE
RECOVERY
CRYPTO
TRUSTED
FEDERATION where enabled
```

## Mandatory hard gates

- no authorization/workspace/provider data leakage;
- no unsafe UNKNOWN external-effect retry;
- recovery does not restore TRUSTED without revalidation;
- derived state rebuild does not rewrite canonical authority;
- secrets do not leak into ordinary memory/history;
- deletion/export semantics are truthful;
- required MUST cases have no skipped/inconclusive results;
- deterministic fault suite passes;
- migration/restore scenarios preserve history and governance;
- known limitations published.

## Fault/recovery scenarios

At minimum:

```text
process crash
projection corruption
partial replay
external dispatch ambiguity
stale repair plan
crypto integrity failure
snapshot restore
policy/provider drift
cross-workspace/federation deny paths
```

## Release claim

Only after this gate may a specific build/config/environment claim:

```text
Vestrace v1.0 — TRUSTED
```

For federation-enabled deployments, `TRUSTED-FEDERATED` requires the federation dependency closure as well.

Qualification remains scoped and revocable/stale; it is not permanent certification.
