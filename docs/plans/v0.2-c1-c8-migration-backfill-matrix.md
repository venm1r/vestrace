## Global migration rules

1. Applied migration files remain immutable.
2. New migrations are monotonic and additive unless a later cleanup migration is explicitly safe after compatibility sunset.
3. Backfill MUST NOT invent `occurred_at`, human actor identity, policy version, semantic Claim status, or evidence authority.
4. Derived tables/indexes may be rebuilt from canonical state; canonical history is never rebuilt from derived state.
5. Every backfill is idempotent or guarded by deterministic completion markers.
6. Large backfills must support bounded batches and restart without duplicate semantic facts.
7. RLS/workspace ownership is present from table creation, not added after data population.
8. New unique constraints are introduced only after duplicate/conflict discovery and explicit reconciliation strategy.

## C1 dependency detail

```text
existing Event.created_at
→ recorded_at

occurred_at
→ NULL unless source proves it

MemoryRevision.valid_from/to
→ NULL/open unless existing domain field proves interval

canonical_hash
→ deterministic canonical serialization of immutable revision content
```

## C2 provenance bridging

Allowed:

```text
legacy MemorySource row with exact source id/revision
→ typed EvidenceRef
```

Forbidden:

```text
free-text source label
→ guessed typed external identity
```

Unresolvable legacy provenance remains legacy evidence with explicit `legacy/unresolved` classification until manually or deterministically upgraded.

## C3 claim bootstrap

No global `INSERT claims SELECT ... FROM memories`.

Initial Claim creation may use only:

- deterministic structured assertion payloads;
- explicit user/system migration rule with provenance;
- later normal mutation/reconciliation path.

## C5–C7 derived-state transition

Search documents, embeddings, pack caches and channel projections are rebuildable. During rollout:

```text
canonical cognitive state
→ build v2 projections in parallel
→ compare/verify
→ switch reads
→ retire legacy projection later
```

No canonical write should depend on successful vector/index rebuild.

## C8 fixture requirements

Qualification migration fixture must contain at least:

- multiple Memory revisions;
- superseded/expired history;
- ambiguous/unknown occurrence time;
- concurrent revision conflict;
- workspace-isolated data;
- provenance chain;
- a contradiction producing Claim conflict;
- old retrieval journal/pack rows;
- rebuildable derived-state corruption fixture.
