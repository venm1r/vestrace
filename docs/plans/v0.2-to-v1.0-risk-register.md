# Vestrace v0.2 → v1.0 — Architecture Transition Risk Register

**Status:** planning baseline  
**Implementation changes authorized:** none

## Risk scale

- `LOW` — local/reversible planning concern;
- `MEDIUM` — can create rework or compatibility debt;
- `HIGH` — can violate architecture/security semantics;
- `CRITICAL` — can invalidate trust/safety claims.

## Stop conditions

A future implementation PR must stop/re-scope if it discovers:

1. need for a second event store/runtime;
2. need to rewrite an already-applied migration;
3. inability to preserve unknown historical semantics without fabrication;
4. requirement conflict between normative specs not resolvable by existing precedence;
5. security/governance guarantee that cannot be tested at the affected entry points;
6. external effect semantics that cannot distinguish ambiguous outcome safely;
7. migration requiring silent authority/trust escalation.

These conditions require a documentation/ADR correction before implementation continues.

## Risk closure rule

A risk is not considered closed by code existence. Closure requires the controlling PR's acceptance/conformance evidence and, where applicable, the phase gate.
