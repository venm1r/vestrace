## Applicability handoffs

- `RET-014` is `NOT_APPLICABLE` before `MemoryMount` exists unless an enabled implementation exposes equivalent mounted cross-workspace retrieval. It becomes mandatory when G4 introduces/enables mount semantics.
- v0.2 may verify only the capability/workspace obligations required to protect Memory/retrieval. This does not claim full `CAP-*`/`IDW-*` governance; G1-G6 complete that boundary.
- AUTONOMY crash/fault safety and TRUSTED incident/revalidation are distinct per ADR-0010.
- Gate PRs verify missing semantics; they do not silently implement them.

## Traceability rules

1. Every applicable normative MUST must have at least one delivery owner and one executable verification path before its claiming gate.
2. Overlap is intentional where one PR establishes a primitive and a later PR generalizes or universally enforces it.
3. `NOT_APPLICABLE` requires explicit feature/configuration evidence; absence of an implementation plan is not applicability evidence.
4. A requirement cannot move to a later claiming gate merely because implementation is difficult; movement requires explicit spec/ADR change.
5. `PASS` may only be claimed from executable evidence, never from this matrix.
6. If a future PR changes a requirement's observable semantics, traceability and the normative catalog must be updated together.
