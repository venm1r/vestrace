# v0.2 Correct — PR Specifications

**Status:** approved documentation plan  
**Target profile:** `CORE + MEMORY`  
**Implementation changes authorized:** none  
**Prerequisites:** PR-0.1 and PR-0.2 planning contracts.

This document expands `PR-C1…PR-C8` from the high-level roadmap into implementation-ready documentation. The sequence is intentionally ordered: temporal identity and evidence come before Claims; Claims come before reconciliation; reconciliation comes before ContextPack truth assembly; qualification closes the milestone.

# PR-C1 — Generic Temporal Event and Memory Revision Model

## Goal

Bring generic Event/Memory temporal semantics up to the standard already demonstrated by Run history.

## Target changes

```text
Event
├─ occurred_at?
├─ recorded_at
├─ correlation_id?
├─ causation_id?
└─ integrity/classification metadata

Memory
└─ state_revision

MemoryRevision
├─ valid_from?
├─ valid_until?
├─ classification
├─ change_reason
├─ created_by
└─ canonical_hash
```

## Migration strategy

Forward-only additive migration.

Backfill rules:

- existing event creation timestamp → `recorded_at`;
- `occurred_at = NULL` unless source data proves occurrence time;
- existing Memory validity remains open/unknown;
- historical actor remains unknown/system-migration if not provable;
- canonical hash uses a deterministic canonical representation.

Never invent occurrence times, validity intervals or human actors.

## Requirements

`TMP-001..007`, applicable `MEM-001..010`, `MUT-001..002`.

## Acceptance

- unknown occurrence time is valid;
- future validity is distinct from recording time;
- expired validity remains history;
- stale `state_revision` mutation is rejected;
- old Memory revisions are immutable;
- canonical hash is deterministic.

## Non-goals

Claims, reconciliation logic and retrieval behavior changes belong to later PRs.

# PR-C3 — Claim / Assessment / Conflict Core

## Goal

Separate stored Memory from semantic assertions and current supported truth.

## Target domain

```text
Claim
ClaimEvidenceLink
ClaimAssessment
Conflict
Supersession/Reconciliation references
```

Not every Memory becomes a Claim. Procedures/tasks and other non-propositional cognition may remain Memory-only.

## Claim states

```text
Proposed
Supported
Contested
Superseded
Expired
Rejected
Deleted
```

`Supported` means supported under current evidence/policy, not absolute truth.

## Conflict rule

Contradictory admissible evidence produces explicit conflict/contested state. No universal latest-timestamp-wins rule.

## Migration

Add new claim/evidence/assessment/conflict tables with workspace RLS. Existing memories are not bulk-converted blindly; migration/import into Claim form must be deterministic or explicit.

## Requirements

`MEM-013..019`, enabling `RET-003`, `RET-008` and later evidence-deletion revalidation.

## Acceptance

- one claim can have multiple supporting sources;
- contradiction marks claim contested;
- contested claim is not silently emitted as uncontested current truth;
- resolving conflict preserves losing/historical evidence;
- removal of last admissible support triggers revalidation.

# PR-C4 — Cognitive Mutation / Reconciliation Service

## Goal

Unify semantic changes under explicit expected-state, provenance and reconciliation rules.

## Mutation envelope

A significant cognitive mutation records:

```text
actor
target
expected state/revision
intent/reason
provenance
resulting revision/fact
```

## Reconciliation classes

```text
DETERMINISTIC
POLICY_GUIDED
SEMANTIC
HUMAN_REQUIRED
```

Rules:

- deterministic reconciliation uses higher-authority state;
- policy-guided result records exact policy version;
- semantic ambiguity remains explicit;
- human-required path cannot auto-complete;
- no semantic latest-wins shortcut.

## Requirements

`MUT-001..008`, supporting `TMP-006..010`.

## Acceptance

- stale mutation is rejected;
- conflicting concurrent mutations do not overwrite silently;
- deterministic and semantic reconciliation are distinguishable;
- policy version is retained;
- reconciliation result links all competing inputs/evidence.

# PR-C5 — Retrieval Exact-revision Hydration and Authorization Boundary

## Goal

Replace the current retrieval shortcut where candidate explanation can become ContextPack text.

## Target pipeline

```text
candidate refs
→ authorization / workspace / classification filter
→ exact revision hydration
→ temporal validity
→ claim/conflict evaluation
→ representation candidate
→ ContextPack assembly
```

## Required properties

- candidate points to exact revision where semantic reproducibility requires it;
- canonical content is hydrated from authoritative cognition, not retrieval explanation;
- current retrieval excludes superseded/expired facts;
- unresolved conflicts surface explicitly;
- inclusion explanation remains metadata, not content;
- RLS/capability/classification gates happen before disclosure.

## Migration impact

May add exact revision/source/policy/generation metadata to retrieval journal and ContextPack persistence.

## Requirements

Relevant `RET-001..008`, `RET-013`, `RET-015`.

## Acceptance

- ContextPack content matches exact authorized revision;
- stale/superseded revision does not appear as current;
- candidate explanation can never masquerade as Memory content;
- unauthorized candidate cannot leak through ranking metadata;
- every included item has provenance and inclusion explanation.

# PR-C6 — ContextPack 2.0 Representation / Section Assembly

## Goal

Implement real semantic ContextPack assembly and representation ladder.

## Section classes

At minimum:

```text
constraints
current facts
critical decisions
open tasks
procedures
supporting details
recent events
history
conflicts/warnings where appropriate
```

## Representation levels

```text
Full
Summary
Atomic
Reference
```

Rules:

- `Reference` is an actual reference representation, not arbitrary truncation;
- Summary/Atomic retain exact source provenance;
- compression never raises authority;
- hard token/content budget is mandatory;
- warnings/degradation travel with the pack.

## Requirements

`RET-004..008`, `RET-013`.

## Acceptance

- correct semantic section placement;
- deterministic hard budget compliance;
- every representation resolves to exact source revision;
- Reference contains no invented semantic paraphrase;
- pack reports degradation/warnings explicitly.

# PR-C7 — Temporal Retrieval + Multi-channel Wiring

## Goal

Make existing temporal intent and channel abstractions operational.

## Temporal modes

```text
Current
KNOWN_AS_OF(t)
VALID_AS_OF(t)
RECONSTRUCTED_AS_OF(t)
Timeline
AllHistory
```

Modes must not be conflated.

## Retrieval channels

Target wiring may include:

```text
exact
structured
full-text
vector (only when ready/qualified)
graph/history as later-safe extensions
```

RRF remains preferred for incomparable channel ranks.

## Failure semantics

- derived channel failure → explicit degraded mode if safe fallback exists;
- no safe fallback → fail closed;
- generation/version changes invalidate stale caches.

## Requirements

`TMP-004..005`, `RET-009..012`, applicable `RET-014..015`.

## Acceptance

- late-arriving evidence produces different KNOWN_AS_OF vs reconstructed results;
- vector/text failure does not silently corrupt current truth;
- multi-channel fusion is deterministic for fixed inputs;
- cache invalidates after relevant memory/policy/classification generation change.

# PR-C8 — CORE + MEMORY Conformance Gate

## Goal

Convert the v0.2 Correct requirement set from inspection candidates into executable evidence.

## Scope

- requirement mapping for every applicable MUST in `ARC/MEM/TMP/MUT/RET` plus foundational security requirements;
- PostgreSQL/RLS integration suite;
- migration-from-current-main fixture;
- HTTP/MCP bypass checks for exposed memory/retrieval surfaces;
- derived-state deletion/rebuild equivalence;
- no external model dependency for correctness gates.

## Qualification semantics

PR-C8 may evaluate the `CORE + MEMORY` profile using the later agreed harness structure, but MUST fail qualification if required MUST cases are skipped/inconclusive.

No higher profile is implied.

## Acceptance / release gate

```text
[ ] all required CORE MUST cases PASS
[ ] all required MEMORY MUST cases PASS
[ ] no required MUST is SKIPPED/INCONCLUSIVE
[ ] workspace isolation negative suite passes
[ ] current/as-of/contradiction golden scenarios pass
[ ] ContextPack provenance and hard budget pass
[ ] migration fixture preserves history/invariants
[ ] derived projections rebuild from canonical state
[ ] known limitations are explicit
```

Only after this gate may the roadmap label **v0.2 Correct** be claimed.
