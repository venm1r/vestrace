## PR-G1 — CapabilityGrant / PolicyDecision Kernel

### Requirements

`CAP-001..004`, `CAP-008..013`, `GOV-011`, `GOV-012`.

### Contract

```text
CapabilityGrant
├─ grant_id
├─ issuer
├─ subject
├─ operation_selector
├─ resource_selector
├─ tool_selector?
├─ valid_from/valid_until
├─ budget_constraints?
├─ risk_ceiling
├─ conditions[]
├─ obligations[]
├─ delegation_policy
└─ lifecycle_state
```

```text
PolicyDecision
├─ decision_id
├─ actor
├─ operation
├─ resource
├─ matched_grants[]
├─ policy_versions[]
├─ effective_risk
├─ budget_state
├─ trust_state
├─ result
└─ evidence_refs[]
```

Decision values: `DENY`, `ALLOW`, `PREPARE_ONLY`, `REQUIRE_APPROVAL`.

### Migration

Existing capability types may map to new grants only when scope/operation semantics are unambiguous. Broad booleans/roles remain templates or legacy permissions until explicitly normalized.

### Acceptance

- default deny;
- expired/revoked grants rejected;
- decision records exact policy version;
- approval cannot bypass missing capability/hard deny/budget/DataPolicy.

## PR-G2 — Universal Authorization Boundary

### Requirements

`CAP-001..004`, `CAP-010..014`, `IDW-001..003`, `GOV-011..012`, `QUAL-007`.

### Entry-point matrix

Governed operations must pass the same application authorization boundary from:

```text
HTTP
MCP
CLI
worker/background job
internal command path
replay/recovery where mutation/effect occurs
federation adapter
```

### Rule

No interface owns authorization semantics. Interfaces construct typed commands/requests; application boundary evaluates authority/policy.

### Acceptance

- direct worker path cannot bypass HTTP-denied operation;
- MCP cannot access broader memory than HTTP for same authority;
- internal recovery does not silently receive global permission;
- policy decision/audit correlation is preserved across surfaces.

## PR-G3 — Delegation Attenuation + Hierarchical Budgets

### Requirements

`CAP-005..007`, `CAP-013..014`.

### Delegation contract

```text
child effective authority =
parent effective authority
∩ explicit delegated subset
∩ child constraints
∩ current policy
```

Delegation fields include:

```text
parent_grant_ref
child_subject
operation/resource subset
max_risk
validity
budget allocation
max_depth
purpose/conditions
```

### Budget contract

Child budget is reserved/subtracted from parent/global budget according to policy. Child usage cannot exceed either child allocation or parent remaining hard ceiling.

### Acceptance

- child cannot widen resource/operation scope;
- child cannot extend expiry beyond parent;
- child cannot raise risk ceiling;
- delegation depth is bounded;
- same delegated budget cannot be double-spent under concurrency.

## PR-G4 — Cross-workspace Sharing v2

### Requirements

`IDW-004..011`, `IDW-013..014`, `RET-014`, `GOV-003`, `GOV-020`.

### Contract

```text
MemoryShareGrant
├─ source_workspace
├─ exact target_workspace
├─ memory/revision selector
├─ allowed operations/content mode
├─ classification ceiling
├─ validity
├─ policy/version
└─ lifecycle

MemoryMount
├─ target_workspace
├─ grant_revision_ref
├─ accepted_at
├─ lifecycle
└─ local policy refs
```

### Migration

Legacy `CrossWorkspaceMemoryGrant` rows are not auto-activated as target mounts. They may be migrated as legacy grants/proposals. Target access begins only after explicit target acceptance.

### Hard rules

- no wildcard target;
- no mount-of-mount;
- no implicit re-share;
- mount is not local Memory;
- local derivative/import uses ordinary Memory lifecycle + provenance.

### Acceptance

- source grant + target acceptance required;
- revoke stops future disclosure;
- historical disclosure audit remains;
- mounted content cannot bypass RLS through direct foreign joins.

## PR-G5 — Federation Trust Boundary

### Requirements

`IDW-012`, `IDW-014`, `GOV-020`, `QUAL-017`.

### Contract

```text
FederationRelationship
├─ remote identity/domain
├─ trust anchors
├─ accepted protocol/profile versions
├─ qualification evidence refs
├─ crypto/governance compatibility metadata
└─ local policy status
```

Remote authority is never imported as local authority. Remote principal is mapped to local identity and receives locally computed effective capabilities.

### Acceptance

- remote `TRUSTED` self-assertion insufficient;
- signed remote qualification still requires trusted signer/local policy;
- federation trust does not imply data disclosure;
- incompatible governance/classification profile fails closed.

## PR-G6 — Govern / Federation Conformance Gate

### Requirements

All applicable `CAP-*`, `IDW-*`, plus governance/security hard gates needed for the enabled profile.

### Required negative scenarios

```text
expired capability denied
revoked capability denied
child escalation denied
modified approved intent invalid
workspace A -> B direct access denied
legacy grant without target mount denied
mount re-share denied
federated self-asserted trust denied
DataPolicy allow without capability denied
capability allow with DataPolicy deny denied
```

### Surface matrix

Each relevant case is exercised through every exposed surface capable of the operation.

### Exit gate

`v0.4 Govern` is claimable only when authorization/isolation hard gates pass with zero bypasses for the declared deployment/profile.
