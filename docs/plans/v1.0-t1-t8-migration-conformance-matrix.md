## T8 — TRUSTED Qualification Gate

Required end-to-end scenarios:

1. crash after external dispatch → UNKNOWN → reconciliation → revalidation;
2. corrupted derived state → deterministic repair → verification;
3. corrupted canonical history → incident/recovery path, not derived overwrite;
4. snapshot restore → replay → derived rebuild → RevalidationRun → trust transition;
5. invalid signature/audit-chain break → containment and trust degradation;
6. secret handling with no plaintext persistence;
7. RESTRICTED model-boundary denial;
8. deletion with backup caveat and verification;
9. governed signed export;
10. federation self-asserted TRUSTED rejected without accepted evidence;
11. qualification baseline invalidated by material environment drift;
12. post-incident targeted requalification.

TRUSTED gate:

```text
all applicable dependency profiles PASS
required REC/GOV/QUAL MUST PASS
security leakage = 0
authority bypass = 0
unsafe UNKNOWN retries = 0
false trust transitions = 0
required SKIPPED/INCONCLUSIVE = 0
known limitations published
```

## Global migration rules

1. No migration fabricates historical trust, incident, policy, crypto or qualification evidence.
2. Existing sensitive data is not duplicated merely to fit new governance tables.
3. Crypto/key metadata references providers; key material stays outside ordinary DB state.
4. Retention/deletion/export workflows use the existing execution runtime.
5. Qualification belongs to exact build/config/environment, never product name alone.
6. TRUSTED status cannot be backfilled from a successful deployment or passing legacy test suite.
