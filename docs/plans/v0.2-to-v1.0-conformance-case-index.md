# Vestrace v0.2 → v1.0 — Global Conformance Case Index

**Status:** documentation-only verification index

## Purpose

Provide one stable inventory of planned conformance cases across all release phases. Detailed semantics remain in the phase matrices.

## Stable case-ID rule

A registered `case_id` is a stable test-contract identifier. Its observable obligation MUST NOT be reused for a different behavior. Refinement may strengthen evidence while preserving the original obligation; a materially different obligation requires a new case ID.

## Phase 0 bootstrap

```text
CONF-CORE-001  Optimistic version conflict is rejected
CONF-MEM-001   Memory revision identity/history remains stable
CONF-RET-001   ContextPack hard budget is respected
CONF-IDW-001   Foreign workspace data is denied
CONF-CAP-001   Missing capability denies protected operation
```

These cases bootstrap traceability; they do not qualify a profile by themselves. Later phase matrices reuse these IDs with the same observable meaning.

## Applicability vs execution result

Applicability is determined before case execution:

```text
APPLICABLE
NOT_APPLICABLE
```

`NOT_APPLICABLE` requires target/configuration-scoped reason + evidence. Missing implementation is not non-applicability.

For an applicable case, execution status is:

```text
PASS
FAIL
SKIPPED
BLOCKED
INCONCLUSIVE
```

Qualification later maps an evidence-backed `NOT_APPLICABLE` decision to `RequirementResult=NOT_APPLICABLE`.

For a required applicable MUST case:

```text
PASS         → eligible evidence
FAIL         → profile fails
SKIPPED      → profile fails
INCONCLUSIVE → profile fails
BLOCKED      → profile incomplete/fails until resolved
```

## Evidence minimum

Every case/applicability decision records at least:

```text
case_id
requirement_ids[]
profile labels
applicability + reason/evidence
status (when applicable)
source_revision
build_digest
suite_version
started_at/completed_at
evidence refs
failure/limitation metadata
```

Higher profiles additionally bind environment/config/provider/backend identities.

## No aggregate-score shortcut

No weighted score can override:

- authorization bypass;
- cross-workspace leak;
- restricted-data leak;
- unsafe external-effect retry;
- false trust transition;
- failed deletion semantics;
- required applicable MUST failure/skipped/inconclusive.
