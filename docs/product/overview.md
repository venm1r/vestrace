# Назначение и границы продукта

**Редакция:** 2026-09-07 · **Baseline репозитория:** `07e2977a`.

**Статус:** Объяснение принятой границы продукта и целевых сценариев.

## Какую задачу решает Vestrace

Система с длительной историей должна не только искать похожий текст. Ей требуется различать источник, интерпретацию, принятое решение, исправление и устаревшее представление. В Vestrace долговременное знание отделено от конкретной модели и от одного запуска агента.

Пример: в документации сначала записано «пакет завершён», затем опубликовано исправление «пакет переоткрыт». Полезный контекст не просто содержит оба фрагмента: он сохраняет их происхождение, не выдаёт старое заключение за текущий результат и обозначает непроверенные части. Это целевой сценарий продукта; его полная приёмка выделена отдельно.

## Memory-first означает приоритет, а не запрет исполнения

Memory Engine — основа хранения; persistent cognition — способность продолжать работу на накопленной, проверяемой основе. Run, governance, retrieval, модели и восстановление нужны, чтобы безопасно использовать и изменять эту память. Новый механизм orchestration оправдан здесь пользой для конкретного цикла работы со знанием, а не наличием такой функции у соседней платформы.

Модель остаётся вычислительным ресурсом. Замена провайдера не должна заменять идентичность знания или автоматически повышать доверие к ответу. Внутренняя память модели и контекст её текущего запроса не являются базой Vestrace.

## Что Vestrace не обещает

Система не доказывает истинность произвольного текста только потому, что он сохранён с provenance. Она не гарантирует exactly-once произвольной внешней операции без необходимых свойств внешнего сервиса. Она не переносит полномочия вместе с экспортированным JSON и не превращает успешную сборку в сертификат безопасности.

Vestrace не следует описывать как готовую замену любому agent framework, самостоятельную LLM, универсальный no-code редактор или просто векторную БД. Поиск и векторы являются механизмами, но не границей продукта.

## Кто получает пользу

Разработчик получает общий контекст для нескольких задач и клиентов. Редактор знания получает историю и контролируемое исправление. Оператор получает наблюдаемые состояния и процедуры проверки восстановления. Доступность конкретных средств для этих ролей определяется текущим реестром, а не этим описанием назначения.

Первое практическое расширение — Memory Workspace: прочитать, проверить, исправить, импортировать и перенести знания. Оно проектируется поверх существующей модели, без второго владельца состояния.
